# Desktop Main v2 구현 대기: 현재 화면과 승인 목업 차이

기준: 데스크톱 미팅룸에서 승인한 Desktop Main v2 목업과 구현 지시서. 비교 대상은 로컬 `main`의 `0180097e` 시점 `index.html`이다. 이슈·DOM·코드 기준점은 아래 최신 확인 기록에 따르며, 완료 전 코드의 동작이나 후속 구현 결과를 확정한 것은 아니다. 목업의 모든 숫자는 샘플이며, 실제 데이터 연결 여부는 후속 구현 시 다시 확인한다. 이 문서는 디자인 승인이나 작업 큐를 변경하지 않는다.

## 최신 확인 기록 (2026-10-11, KST)

- GitHub 이슈 [#36](https://github.com/mj94920/stockbook/issues/36): `open`, `in-progress`. [#37](https://github.com/mj94920/stockbook/issues/37): `open`, `queue`. 두 이슈 모두 완료·병합 조건을 충족하지 않았다. 확인 시점의 이슈 상태이며 작업 큐는 변경하지 않았다.
- 원격 `main`의 HEAD는 `0180097e261652771352ddf8d845610b2b3ec4eb`로, 아래 비교에 사용한 로컬 커밋과 같다. #36 작업 브랜치 `claude/issue-36-20261005-074730`의 HEAD는 `fbf0866519c2225f9a881b579c336393da65bc0e`이며 아직 `main`에 병합된 결과로 취급하지 않는다.
- 현재 `main`의 DOM에서 `#mdiWorkspace`, `#mdi-panel-watchlist`, `#mdi-panel-trading`, `#mdi-panel-portfolio`, 전종목/관심종목 내부 탭(`.mdi-ptab-bar`), `#allStockTable`, `#watchlistBody`를 다시 확인했다. 헤더의 `#hdrIdxList`, `#hdrAssetGroup`, `#hdrKisBadge`, `#hdrWsBadge`와 레일의 `#apiStatusBtn`도 확인했다. 이는 현재 코드의 존재 확인이며, #36·#37 완료 후 구조와 동작을 다시 대조해야 한다.
- 판단: 승인 목업의 후속 구현은 보류한다. 이 문서의 40:60 배치·라이트 시각 기준·액션 강조 순서는 유지하고, 두 이슈 완료 후 이미 반영된 항목을 제외한다.

1. #36과 #37 완료 후 최신 `main`과 이슈·큐 상태를 다시 읽고, DOM과 이 표의 각 차이를 유지·해결·변경으로 표시한다.
2. 남은 범위를 데스크톱 UI PR 단위로 확정한다. 디자인·기능의 새 결정이 필요한 항목은 데스크톱 미팅룸으로 돌린다.
3. 구현 시 기존 DOM ID·기능·데이터 계산을 보존하고, `npm test`와 스모크 테스트 및 다크/라이트 화면을 확인한다. `queue`·`automerge` 라벨은 부여하지 않는다.
