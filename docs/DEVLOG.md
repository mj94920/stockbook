# StockBook 개발 기록

## 2026-11-07 · 빠른 매도 및 실현손익 수익률

- 일반·빠른 매도는 같은 평균단가 공식을 사용한다. 손익은 `(매도가 − 평균단가) × 매도 수량`, 수익률은 `(매도가 − 평균단가) ÷ 평균단가 × 100`이다. 기존과 같이 수수료·세금 차감 전 기준이다.
- 과거 매도는 저장된 수익률을 우선 표시한다. 값이 비어 있으면 거래에 기록된 매수단가를 사용한다. 기존 빠른 주문 표시가 있고 매도가·수량·총액·손익으로 당시 평균단가를 역산할 수 있는 건도 조회 시 계산한다. 나머지는 확인 불가로 표시하며 조회로 원본을 저장하지 않는다.
- 요약에 전체 매도 건수와 수익률 확인 건수를 함께 표시한다. 매도 건별 단순 평균에는 확인된 값만 포함하며 실제 0%도 포함한다.
- 가상 예시에서 평균단가 100원, 매도가 120원, 수량 4주는 두 경로 모두 +80원과 +20%다. 과거 빠른 매도 +20%, 실제 0%, 근거 부족 1건을 조회하면 전체 3건 중 2건으로 평균 +10%를 표시한다.
- 격리 작업 사본에서 `npm test`를 실행했다. 정적 검사, 단위·브라우저 테스트 96개, 스모크 검사를 통과했다. Playwright는 설치된 Chrome으로 실행했고, 매도 검증은 별도 브라우저 컨텍스트의 가상 기록을 사용했다.

## 2026-11-07 · 투자일지의 계획과 실제 거래

- 기존 투자일지 상세에 읽기 전용 복기를 추가했다. 거래와 새 일지 초안이 같은 저장 작업에서 함께 생성될 때만 둘에 공통 참조를 남긴다. 기존 일지를 이름이나 날짜로 역매칭하지 않는다. 연결 누락·중복·충돌은 확인 불가로 표시한다.
- 연결된 실제 거래는 거래일·단가·수량을 표시한다. 매도 손익은 원본 기록을 읽고 수익률은 기존 실현손익 로직을 재사용한다. 복기를 조회해도 거래, 일지, 결과 메모, 교훈을 저장하거나 변경하지 않는다.
- 진입 당시 계획을 입증하는 스냅샷이 없으므로 현재 목표가·손절가는 그대로 기존 일지에만 표시한다. 진입 당시 계획 비교에는 별도의 사전 계획 기록이 필요하다. 한 일지에 추매와 여러 매도를 묶으려면 각 체결과 보유 구간을 명시적으로 연결하는 선행 작업이 필요하다.
- TraderMonty의 [trader-memory-core](https://github.com/tradermonty/claude-trading-skills/tree/main/skills/trader-memory-core)와 [trade-performance-coach](https://github.com/tradermonty/claude-trading-skills/tree/main/skills/trade-performance-coach)의 로컬 사본에서 계획과 실제의 분리, 근거 부족의 표시 방식을 참고했다. 외부 구현 코드를 복사하지 않았다. 원본의 라이선스는 [MIT](https://github.com/tradermonty/claude-trading-skills/blob/main/LICENSE)다.
- 기준 커밋의 격리 사본에서 `npm test`를 실행했다. 정적 검사와 테스트 98개, 스모크 검사를 통과했다. 가상 거래로 빠른 매수의 연결 저장, 새로고침 후 복원, 명시적으로 연결된 매도와 미연결 기록의 표시를 확인했다.
