# Stock Book UI/UX 1차 개편 계획

> 출처: 노션 「Stock Book UI/UX 1차 개편 기획 미팅 - 2026-09-22」 (MJ).
> 이 문서가 개편 작업의 기준이다. 단계별 작업은 GitHub 이슈(`queue` 라벨)로 하나씩 자동 진행된다.

## 0. 제품 성격 (변경 금지 전제)

- Stock Book 의 핵심은 **통합 포트폴리오 관리 + 종목 탐색 + 투자 기록 + 실시간 가격 확인**. 실제 주문은 목표가 아니다.
- 호가창은 실주문이 아닌 **실시간 가격 확인·HTS 감각**용 보조 기능으로 유지.
- 보유종목 실시간 가격은 핵심 기능으로 유지.
- KIS WebSocket 은 등록 가능 종목 수에 제한 → 전종목 실시간은 목표 아님.
  실시간 구독 우선순위: **보유종목 > 현재 선택 종목 > 관심종목 > 기타**.
- 데이터: 실시간·계좌 = KIS / 전종목·기업 = 네이버(Npay 증권)·KRX·Yahoo. DART 는 기본 의존성으로 쓰지 않는다.
- **종목 탐색·기업분석 패널은 완성도가 높으므로 대수술하지 않는다.**

## 1. 디자인 원칙

- 다크 네이비 기반 금융 도구 분위기 유지. 라이트 모드도 동등하게 지원.
- 과한 카드형·큰 라운드·그림자·글래스(blur)를 줄이고 **얇은 경계 + 명확한 계층**.
- 글꼴: 한글 Pretendard/NanumSquare 계열, 숫자 Inter 계열(tabular-nums).
- 실시간 가격 변화 애니메이션은 보유종목 등 필요한 곳에만.
- 모든 패널·팝업·설정·사이드바가 **같은 디자인 토큰**을 사용해 한 제품처럼 보이게.
- Electron GPU 합성 레이어 버그: 모달/오버레이에 `backdrop-filter` 금지 (CLAUDE.md §3).

## 2. 전체 구조

좌측 사이드바 + 상단 헤더 + 중앙 작업영역 + 우측 드로어/모달의 4계층.
화면 중심축: **시장/종목 → 내 자산 → 뉴스/정보 → 기록**.

## 3. 영역별 요구사항

### 3-1. 좌측 사이드바 (최우선)
- 메인 메뉴: 종목 탐색 / 포트폴리오 / 뉴스·시황 / 매매기록 / 투자일지
- 하단 시스템 메뉴: 계좌·API / 데이터 / 설정
- 로그인·설정·API 등 중복 진입 요소 정리
- 접기 상태 = 아이콘 전용 모드, 현재 메뉴 표시와 연결 상태 유지

### 3-2. 상단 헤더
- 지수: 텍스트 나열 → **미니 카드형**. 기본 KOSPI / KOSDAQ / USD-KRW / NASDAQ, 선택 S&P500 / DOW / SOX / JPY-KRW 등
- 카드마다 지수명 · 현재값 · 등락 · 등락률 계층 표시
- 시장 지표와 자산 요약을 분리. 자산 요약 카드: 총자산 / 예수금 / 평가손익 / 당일손익

### 3-3. 날짜·캘린더 → 시장 일정 센터
- 기존 구현(기업 이벤트/경제지표 탭, 월간 달력, 이벤트 점, 사용자 일정, D-day, Investing.com·한국은행 링크)은 **구조 유지, 표현 개선**
- 420px 고정 우측 패널 → 더 넓고 실용적인 시장 일정 센터
- 경제지표: 시간 / 국가 / 실제 / 예상 / 이전 / 중요도 표시 공간
- 날짜 셀: 점 나열 대신 **가장 중요한 일정 + 추가 n건**
- 헤더 날짜 옆: '오늘 주요 일정 n건' 또는 가장 가까운 중요 일정만

### 3-4. 뉴스/시황 → 정보센터
- 외부 링크 모음이 아닌 HTS식 정보센터
- 상단 탭: 시장뉴스 / 종목뉴스 / 공시 / 경제지표
- 좌: 시간·출처·종목·제목 목록 / 우: 상세 미리보기 · 관련 종목 · 원문보기 · 기업분석 이동
- 외부 페이지 임베딩보다 데이터를 자체 UI로 구조화, 원문만 외부 브라우저로

### 3-5. 포트폴리오 (핵심 화면)
- 총자산·예수금·평가손익·당일손익 상단 요약 카드 통일
- 자산/예수금 수정 → 공통 모달 규격
- 보유종목 표·실시간 가격 반영 기능 유지

### 3-6. 매매관리
- 역할 = **호가 확인 + 거래 기록** (실주문 아님). 호가창 유지
- 매수/매도 기록은 보조 기능으로 축소 가능, 계산기는 접이식/보조 탭

### 3-7. 투자일지
- 기능 유지, 작성·수정·삭제 흐름 정돈
- 종목 연결 · 거래 연결 · 태그 · 금액 자동계산을 명확히 노출

### 3-8. 설정 → 운용 허브
- 카테고리: 일반 / 화면·테마 / 시세·실시간 / 계좌·API / 포트폴리오 / 종목 분류 / 뉴스·시황 / 데이터 관리 / 알림 / 고급
- UI 밀도: 넓게 / 기본 / 조밀하게
- KIS 실시간 구독 우선순위 설정
- 설정/API/로그인 진입 중복 제거

### 3-9. 팝업·모달 공통 규격
- 자산/예수금/평단/목표가/계좌/API/로그인 등 모든 팝업을 하나의 규격으로
- 크기 Small / Medium / Large
- 제목 · 닫기 버튼 · 입력 필드 · 확인/취소 위치 · 숫자 표기 규칙 통일

### 3-10. 종목 분류 (2차 고도화 대상, 1차는 구조 준비만)
- 단일 그룹 → **업종 / 세부산업 / 사용자 태그** 다중 분류 (예: 반도체 → 반도체 장비 → HBM·AI·수출주)
- 테마별 탭은 별도 화면보다 필터/태그 방식

## 5. 1차 완료 기준

- 기존 종목 탐색 · 포트폴리오 · 호가 · 실시간 시세 · 투자일지 기능 유지
- 사이드바의 투자 기능 / 시스템 기능 구분 명확
- 헤더의 지수 · 자산 · 상태 정보가 한눈에 읽힘
- 캘린더가 실제 투자 일정 확인 도구로 보임
- 뉴스/시황이 링크 모음이 아닌 정보센터 형태
- 설정 · 계좌 · API · 자산 수정 모달이 동일 디자인 시스템 사용
- 라이트/다크 및 주요 창 크기에서 UI 깨짐 없음

## 7. 단계 작업 공통 규칙 (Claude 용)

- 범위는 **해당 단계 이슈에 적힌 것만**. 다른 단계 영역을 미리 고치지 않는다.
- 기존 기능의 함수명·IPC·데이터 구조(state, localStorage 키, stockbook-data.json)는 바꾸지 않는다. 바꿔야 하면 마이그레이션 포함.
- 기존 DOM id 를 JS 가 참조하고 있으면 유지하거나 참조를 함께 고친다 (`grep` 으로 전수 확인).
- 2단계에서 만든 디자인 토큰만 사용한다. 새 하드코딩 색상 금지.
- `npm test` 통과 필수. CI 가 남기는 스크린샷(smoke-shots 아티팩트, 다크/라이트)으로 결과를 확인할 수 있다.
- 커밋 메시지: 단계 = `feat(ui): …` / 수정 = `fix(ui): …`.
