# StockBook Android 2.0 — UI v2 시각 검토 패키지

> **⚠️ Android(모바일) 전용 시안이다. PC 데스크톱 UI(`index.html`·`splash.html`)에 적용하지 않는다.**
> 하단 탭·모바일 카드 레이아웃·색·간격 등 어떤 요소도 데스크톱으로 옮기지 않는다. PC UI 기준은 `docs/UI-REVAMP-PLAN.md` 와 UI 2차 이슈(#35~#41)다.
> 이 시안의 구현은 `CLAUDE.md` §8 의 Android Gate 이후 `android/`(Kotlin) 에서만 한다.

## 산출물
- `png/`: 18개 화면, 각 780×1688px (390×844dp @2x)
- `source/`: 동일 화면의 편집 가능한 SVG 원본
- `overview.png`: 전체 화면 콘택트시트
- 구현 코드·데이터 계약·저장소 파일 변경 없음

## 시각 방향
- 밝은 회백색 배경, 흰 카드, 네이비 기본색, 빨강 상승·파랑 하락
- 하단 5개 탭, 16dp 카드 반경, 16dp 좌우 기본 여백
- 금액 예시는 XXX 표기; 가정 의존 화면은 `임시 O-n` 태그
- 신호 상태와 사건 분리, 규칙 판정 고지 유지
- 자산은 비중 막대 사용, 통화별 별도 카드
- 관찰/메모 빠른 기록에는 가격·수량·금액 필드 없음

## 원본 명세와 달라진 점 / 추가 제안
1. 종목 목록·검색을 별도 검수 화면으로 분리했다.
2. 종목 상세의 데이터 부족을 별도 화면으로 분리했다.
3. 첫 실행, 빈 목록, 오프라인, 갱신 실패, 미해결 항목을 각각 독립 검수 화면으로 분리했다.
4. 신호 상세·종목 식별 해결·백업 복원 확인을 별도 시트로 그렸다.
5. 시세 갱신 시각은 실제 값이 아닌 `예시 데이터`로 표기했다.
6. 화면의 일부 항목은 접힌 상태 또는 대표 행만 표현했다. 상세 서식의 모든 필드를 없앤 것이 아니다.

## Contract Gate 미확정 / 데이터 요구사항
- O-1: Android 사용자 데이터 출처·파일 복원 규격
- O-2: 거래 직접 입력 범위
- O-3: 해외 자산 통화별 집계
- O-4: 신호 라벨과 규칙 근거 표현
- O-5~O-10: 그룹, 계좌, 현금, 임시저장, 알림, 내보내기
- 데이터 기준 시각/가격 종류, 데이터 부족 판정에 필요한 N/M, 신호 이벤트 발생일, 종목 식별 후보 검색, 백업 호환성 검증 결과는 계약 확정 전 가상 표시다.

## 360dp 및 글자 200% 검수 상태
- 390dp 정적 목업 제작 완료.
- **360dp 및 시스템 글자 200%에서 실제 동적 레이아웃 통과를 주장하지 않는다.** SVG는 고정형 디자인 원본으로, 시스템 폰트 배율에 반응하지 않는다.
- 구현 인계 기준: 360dp에서 양쪽 16dp 여백, 숫자 말줄임 금지, 금액·등락률 두 줄 허용, 터치 타깃 48dp 이상, 긴 버튼 문구 줄바꿈, 스크롤 가능한 시트와 키보드 회피를 반드시 재검증한다.
- 현재 정적 목업은 일부 작은 칩·시트 항목에서 48dp 터치 영역이 시각적으로 보이지 않으므로 **접근성 구현 검증이 남아 있다**.

## 주의
- 이 패키지는 시각 시안이며, 실제 Android 앱 UI 구현물이나 데이터 계약 확정본이 아니다.
- `AGENTS.md`와 `CLAUDE.md §8`은 이 실행 환경에서 직접 확인하지 못했다. 사용자가 제공한 게이트 제약을 준수했으며, 저장소 반영 전 두 파일을 다시 대조해야 한다.

### 검토 사항 (미확정 · 후속 필요)
1. **#50 Signal 구분.** 화면은 신호를 세 가지로 나눠 표시한다.
   - **상태**: 정배열, 역배열
   - **사건**: 골든크로스, 데드크로스
   - **판정 불가**: 데이터 부족

   현재 #50 의 Signal 초안에는 이 셋을 구분하는 필드가 없다. #50 또는 Contract 에서 구분을 정의해야 한다. 구체적인 데이터 계약(필드 이름, 값 목록, 사건 발생일 기준)은 미확정이다.
2. **O-1 / O-2: Android 거래 입력과 사용자 데이터 정책.** 다음이 정해지지 않았다.
   - Android 에서 거래를 직접 입력할지
   - 사용자 데이터의 출처를 PC 와 Android 중 어디로 둘지
   - 동기화와 충돌 처리 방식, 백업 파일 규격

   다음 화면은 **임시**다. 정책이 확정된 뒤 다시 그린다.
   - 06 자산의 `+ 거래 기록`
   - 11 첫 실행의 `거래 기록`
   - 18 백업 복원
3. **홈 자산 총액 표기.**
   - 서로 다른 통화의 금액을 섞어 합산하지 않는다. 홈 총액은 **KRW 기준 총액**이다.
   - 해외 자산(USD 등)은 06 처럼 통화별 카드로 따로 표시하고, KRW 총액에 환산해 넣지 않는다.
   - 표기가 모호하다는 판단에 따라, 저장소 등록 때 다음 세 화면의 자산 제목에 `KRW` 를 붙였다. SVG 원본과 PNG 를 함께 수정했다.

     | 화면 | 변경 후 제목 |
     |---|---|
     | `01-home` | `내 자산 · KRW` |
     | `13-offline` | `내 자산 · 저장 데이터 · KRW` |
     | `14-refresh-error` | `내 자산 · 저장 데이터 · KRW` |

   - `overview.png` 콘택트시트는 이 수정 **이전** 상태다. 개별 PNG 가 기준이다.
4. **접근성 검증 전.** 다음 세 가지는 아직 검증하지 않았다.
   - 360dp 폭
   - 시스템 글자 크기 200%
   - 최소 48dp 터치 영역

   위 "360dp 및 글자 200% 검수 상태" 절의 인계 기준대로, 실제 목업으로 다시 검증해야 한다. 다음 디자인 작업이 이것이다.
