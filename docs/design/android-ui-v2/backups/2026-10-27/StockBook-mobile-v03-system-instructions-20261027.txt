StockBook 모바일 v0.3 — 시스템룸·디자인 구현룸 인계 지시서
기준일: 2026-10-27 (한국)

1. 인계 대상과 승인 경계
사용자는 최신 통합 목업의 방향을 수용하고 에셋 저장 및 시스템 지시서 작성을 요청했다. 이번 묶음은 디자인 기준의 보존·인계이며, 모든 화면·데이터 계약·구현 게이트가 일괄 승인됐다는 뜻이 아니다. 기존 v0.2와 사용자 시험구동한 시장 탐색 구조를 보강한다. 승인된 구조를 재설계하지 않는다.
이번 작업에서 GitHub 업로드·PR 작성·병합·배포는 수행하지 않았다. 이전 PR의 현재 상태도 이번에 조회하지 않았다. GitHub에 반영할 때는 완전 승인된 범위만 선별하며, 사람 머지 원칙을 유지한다.

2. 무엇부터 열 것인가
preview/mobile-v03.html: 최신 통합 기준. 홈에서 시작하며 설정 > 화면 테마에서 시스템 설정 / 라이트 / 다크를 선택한다. 시작 선택은 기존 라이트를 유지했다. 앱 기본 테마 정책은 별도 확정 없이 변경하지 않는다.
source/mobile-v03.html: 해당 인라인 원본. 독립 화면별 구버전을 합쳐 새로운 기준으로 삼지 않는다.
preview/*-states-light.html 및 *-states-dark.html: 보유·뉴스·재무·경제일정의 상태 검토용. 상부 상태 버튼은 검토 도구이며 제품의 신규 탭이 아니다. 이 상태 시안 전부가 통합본의 실제 데이터 상태 머신에 연결된 것은 아니다.
assets/embedded/: 위 목업들에 실제 포함된 data URI 이미지를 중복 제거하여 보존한 바이트 원본. 어떤 파일이 어떤 원본 목업에서 추출됐는지는 asset-index.json을 참조한다.

3. 유지할 구조와 디자인
하단 도구: 홈 / 시장 / 종목 / 자산관리 / 일지. 홈 상부의 발견 진입을 유지한다. 설정·인증 등 공통 기능은 하단 티커 바로 위에 두는 기존 기준을 유지한다. 스크롤 고정 여부는 미결정이다.
설계 순서: 하단 도구 → 세부탭 → 카드 구성·순서·밀도 → 카드 내부 조작 → 상세 연결.
각 도구의 세부탭 안에서 정보 카드가 이어진다. 카드 높이는 내용에 맞추며 빈 공간을 메우기 위해 정보를 늘리지 않는다. 보유·관심 목록에 임의의 펼침 기능을 추가하지 않는다.
라이트는 밝고 부드러운 둥근 형태, 진한 본문, 절제된 파스텔을 유지한다. 다크는 별도 배색이며 순검정·옅은 본문으로 처리하지 않는다. 클레이 아이콘은 작은 크기로 사용한다.
오늘 뜨는 업종·테마는 세로 행 목록형 카드 하나다. 작은 아이콘·이름·보조 정보·등락 수치와 하단 더 보기를 유지한다. 큰 업종 타일 그리드나 별도 시장 메인을 만들지 않는다.
탐색: 업종·테마 → 산업·사업 분야와 관련 기업 → 종목 상세. 기존 방에서 새로 만든 시장 메인·전체 업종 그리드는 기준에서 제외한다.

4. 기능별 적용 원칙
종목: 목록 → 종합 / 사업 / 재무 / 지표 / 뉴스·일정. 관련 기업의 상세 연결과 뒤로가기 맥락을 유지한다.
뉴스: 일반 기사 / 공시로 분류하고 언론사는 필터로 선택한다. 언론사별 묶음·우선 순서 없이 시간순으로 섞는다. 참고 언론사는 연합뉴스, 연합인포맥스, 매일경제, 블로터, 지디넷코리아다. 목업의 보관 기사·가상 수치를 최신 데이터라고 표시하지 않는다. 원문 기사 표시·수집 방식과 출처 계약은 시스템룸에서 확인한다.
자산: 국내·원화 기준. 총자산에 예수금을 한 번만 포함한다. 예수금 세부 정보는 상세 모달에서 다룬다. 해외 투자·달러 자산 UI를 추가하지 않는다.
일지: 한 종목의 투자 과정에 언제/얼마에 매수·매도했는가, 왜 했는가, 어느 계좌에서 얼마나 했는가, 손익, 투자 중 멘털 상태를 담는다. 매수·매도·메모를 임의의 별도 탭으로 분리하지 않는다. 주제별 접기·펼치기와 입력 보존을 유지한다.
거래: 매매창 거래가 자동 기록되는 기존 시스템 방향을 유지한다. 직접 기록은 보조 경로다. 목업의 저장 실패·재시도 후 완료는 로컬 시연이며 실제 주문·DB 저장·영속 일지 연결이 아니다. 입력 값은 확인·완료·상세·일지·정정 검토에서 같은 거래로 이어져야 한다.
테마: 시스템 설정 선택 시 OS 테마 변경을 따라가고, 라이트/다크 직접 선택 시 OS 변화가 덮어쓰지 않는다. 선택 유지·앱 재시작 정책은 실제 구현에서 계약 및 기존 설정 정책에 맞춰 검증한다. HTML 목업은 영속 설정 저장을 하지 않는다.

5. DC-1 / DC-2와 미확정 사항
DC-1: B 조건부 승인. { settled, amount, pending } + asOf. settled=당일 예수금, pending=정산 예정분, amount=거래 반영 전체. basis의 local_ledger / broker_snapshot 의미를 유지하며 d0/d2 의미로 재사용하지 않는다.
레거시 settleDate 부재는 UNKNOWN 또는 동등한 미확인 상태로 보존한다. 체결일 결제 또는 d0=d2로 간주하지 않는다. 기존 표시값을 보존하는 compatibility 처리와 실제 결제일 의미를 분리한다. 구체 이관 규칙 및 신규 거래 휴장일 데이터 출처는 별도 결정한다. opening이 레거시 차이를 흡수한다는 문구로 미해결 정책을 대체하지 않는다.
DC-2: A 승인. 원 이벤트를 참조하는 void, 정정은 void + 신규 이벤트 및 correctionOf 연결. 물리 삭제·원 이벤트 재작성 금지. 연결 일지를 자동 삭제하지 않는다. 표시·연결 세부 정책은 후속 계약으로 확정한다. ledger_revision은 #64(v3)에서 도입하고 #29 v1을 확장하지 않는다.
예수금 당일/정산 예정, 취소·정정, CSV 화면은 남은 계약이 확정될 때까지 ‘임시 · 계약 미확정’ 표시를 유지한다. 이번 문서로 상태 이름·이관 규칙을 확정하지 않는다.
기존 미팅룸 PR 순서 결정: #72 → #71. #72 이후 #71 최신 main 재정합·충돌 해결·문구 수정·DC-1/DC-2 재검수 후 사람 머지. 이미 실행됐다는 보고가 아니며 현재 상태는 시스템룸에서 확인한다.
industryKey / themeKey는 시스템 계약 절차에서 확정한다. 분류 범위·기업 연결·선정 기준·집계 등락률은 Claude 검토와 미팅룸 결정 대상이다.
문서 반영은 구현 승인으로 해석하지 않는다. Android Gate와 Shared Contract 확인 전 구현 착수 금지 원칙은 유지한다.

6. 상태 표시
실제 0개/0건과 미수신·미연결은 다르다. 보유 없음·필터 결과 없음은 확인된 빈 결과에서만 사용한다.
조회 실패·오프라인은 마지막 수신 자료와 수신 시각을 남기며 최신 자료처럼 보이지 않게 한다.
재무 일부 누락은 0으로 그리지 않는다. 미수신 구간의 선을 연결하지 않으며 표에도 미수신으로 표시한다.
일정 없음, 발표 전, 발표값 미수신, 일정 데이터 미연결을 구분한다. 과거 수신 상태를 최신 발표 상태로 단정하지 않는다.

7. 에셋·로고 경계
70종은 업종·분야·테마·상품·fallback을 합친 디자인 후보 묶음이다. 70개 업종 또는 승인된 제작용 에셋이 아니다. 이번 embedded 이미지 묶음도 전체 70종 원본 세트가 아니다.
과거 03 SB 심볼 + 선택 글씨체 + Stock Book 표기 지시는 기억하되, 사용자가 로고와 배치 재작업을 코딩 단계로 미뤘다. 현재 통합본의 문자 표기는 임시다. 확정 문자로고·폰트·Android 전경/배경·벡터 원본을 새로 만들거나 적용했다고 보고하지 않는다. 기존 전달 브랜드 ZIP 원본은 이번 묶음에 포함하지 않았다.
기업 로고는 공식 상징을 확인해 적용한다. 긴 기업명에는 상징만 넣어도 된다. ‘삼’ 같은 임의 이니셜은 제작용 로고로 사용하지 않는다. 시안의 기업 그림은 사용권·정확성·제작용 규격 검증을 대체하지 않는다.
정확한 Android 리소스 파일명·밀도·벡터·접근성 대체 텍스트는 구현 담당이 원본 검토 후 확정한다.

8. 검증 결과와 남은 확인
브라우저 시연 검증: 주요 화면 왕복, 설정/CSV/인증 닫기, 발견 → 종목 → 발견, 거래 수량·가격 전달, 저장 실패/재시도 예시, 상세/일지/정정 검토, 금액 가리기/복원 통과.
테마: OS 밝음/어두움 변경 추종, 명시적 라이트/다크 우선 유지 통과. 홈의 테마별 카드 높이 동일 확인.
320px: 다섯 도구, 긴 종목명·긴 일지 입력 시 문서 가로 넘침 없음 확인. 모달 키보드 순회에 select/textarea/link를 포함했다. 검사한 흐름에서 JS 런타임 오류 없음.
한계: 로컬 검사 브라우저에 한국어 글꼴이 없어 한국어 글꼴 모양·정밀 줄바꿈은 실기기 검수 완료가 아니다. 네이티브 키보드·접힘 화면·글꼴 확대·회전·백그라운드 복귀·실제 저장 복구·실데이터 연결은 미검증이다.
설정 모달 포커스 순회 및 실제 Android 뒤로가기, 입력 중 나가기/실패/재시도에서 초안 보존을 실기기로 별도 확인한다.

9. 시스템룸 작업 순서
① 이 ZIP을 풀어 preview/index.html과 최신 통합본을 확인한다.
② 기존 구현·계약·게이트 현황과 대조해 디자인 적용 가능 범위와 보류 범위를 보고한다.
③ 승인 범위에서만 UI 적용 계획·에셋 매핑·데이터 출처/상태 매핑을 작성한다.
④ 게이트 충족 후 담당 브랜치에서 구현한다. HTML 런타임 색상 치환을 Android의 제작용 테마 구현으로 그대로 복제하지 말고 의미별 테마 토큰으로 옮긴다.
⑤ 규격 반영 / 빌드 성공 / 디자인 만족 / 실기기 통과를 구분해 보고한다. 자동 병합·배포하지 않는다.
