# StockBook Industry Icon Tile 전체 대응 묶음 v0.3

먼저 `gallery.html`을 열어 전체 아이콘을 확인하세요. `market-list.html`은 작은 타일과 금융정보의 배치 검토용이며 수치는 예시입니다.

## 범위

승인된 12종은 스타일 기준입니다. 이 묶음은 그 스타일을 확장한 **개별 이미지 70종**을 목표로 제작합니다. 실제 생성 수와 누락 여부는 `coverage.json`에서 확인할 수 있습니다.

- 업종·세부 산업: 42종
- 테마: 9종
- ETF·투자 분류: 16종
- 기본 아이콘: 3종

현행 StockBook 코드 `_getAutoSector()`의 31개 반환값과 `_getAutoETFTheme()`의 22개 반환값은 전부 대응표에 포함합니다. ETF의 배터리·반도체처럼 의미가 같은 항목은 기존 에셋을 재사용하므로 53개 분류 항목이 반드시 53개의 서로 다른 이미지를 요구하지는 않습니다. 업종·테마·ETF 항목의 소속 자체는 합치지 않습니다.

목업의 업종 10종·테마 6종, 승인 시안의 대표 12종, 시스템 제안서의 반도체 하위 분야 예시, 사용자 레퍼런스에서 언급한 알루미늄·반도체패키징·디스플레이장비를 함께 대비했습니다. HBM·수출주는 저장소 UI 기획에 등장하는 예시를 위한 디자인 후보입니다.

**현재 확인된 자료에 대한 대응 세트입니다. 앞으로 사용할 모든 분류가 확정되었다는 뜻은 아닙니다.** 외부 공급자가 주는 자유로운 업종명, 사용자의 임의 태그, 새로 생성되는 테마까지 유한한 이미지 묶음으로 전부 보장할 수는 없습니다. 새 항목은 대상 목록에 추가한 뒤 같은 스타일로 확장합니다.

## 파일 구조

- `assets/industry/`: 업종과 세부 산업 PNG 원본
- `assets/theme/`: 테마 PNG 원본
- `assets/fund/`: ETF 및 투자 분류 PNG 원본
- `assets/fallback/`: 미지원 업종·미지원 테마·기타 ETF
- `asset-manifest.json`: 디자인 에셋 식별자, 이미지 경로, 모티프, 픽셀 크기
- `mapping-review.json`: 현행 코드 표시명·목업 designKey·제안서 예시 키의 대응표
- `design-tokens.json`: 표시 크기·모서리·광원·배경 팔레트 제안
- `coverage.json`: 현행 분류 대응과 누락 확인
- `preview-*.png`: 실제 파일을 브라우저에서 배치한 검토 이미지
- `qa-render.json`: 이미지 로딩·가로 넘침·목록 표시 규격 확인 기록
- `docs/`: 스타일 규격서, 승인 스타일 기준 이미지, 시스템 제안서, 반도체 예시 데이터, 현행 분류 추출 목록

## 원본과 표시 규격

PNG 원본은 **배경이 채워진 사각형 마스터**입니다. 개별 이미지 생성에서 생기는 외곽 차이를 피하기 위해 UI에서 동일한 라운드 클리핑을 적용하는 방식으로 통일했습니다. 48dp 표시에서 모서리 반지름 12dp, 40dp 표시에서 10dp를 사용합니다. 웹 검토판은 `border-radius:25%`를 사용합니다. Android에서는 동일한 모양의 클리핑을 적용합니다. Android 구현 파일은 포함하지 않습니다.

**모서리 밖이 투명한 최종 타일 PNG, 1×·2×·3× 내보내기는 포함하지 않습니다.** 이 묶음은 원본 마스터와 표시 규격을 제공합니다. 원래 v0.2 규격서의 투명 타일 납품 제안과 구별하세요. 원본을 라운드 클리핑 없이 직접 표시하면 사각형으로 보입니다.

생성에는 내장 이미지 생성 도구를 사용했습니다. 공통 지시: 승인된 스타일의 단일 3D 픽토그램, 매트한 소재, 좌상단 광원, 약한 접지 그림자, 캔버스 점유율 약 60~65%, 저채도 단색 배경, 글자·로고·장면 장식 없음. 개별 모티프와 배경 목표값은 manifest에 있습니다. 생성 원본의 오브젝트 크기·배경 색·그림자가 수치 토큰과 정확히 같다고 주장하지 않습니다. 최종 에셋 적용 전 광학 보정과 정밀 색 보정 여부를 검토합니다.

## 코덱스 전달 지시

1. `gallery.html`, 승인 스타일 기준 이미지, `STYLE-SPEC-v0.2.md`로 화풍을 확인한다.
2. `coverage.json`과 현행 코드 목록으로 필요한 항목이 대응됐는지 확인한다.
3. 시스템 담당이 확정한 `industryKey`·`themeKey` 목록을 받은 뒤 UI 매핑을 작성한다. 이 묶음의 `iconAssetKey`는 **디자인 파일 식별자**이며 StockBook 종목의 영속 `assetId`와 무관하다.
4. `mapping-review.json`은 검토용이다. 기존 표시명을 새 계약 키로 그대로 고정하거나 예시 키를 확정 계약으로 삼지 않는다.
5. 알 수 없는 키는 기본 타일로 표시하되 업종명과 탐색 기능을 유지한다. 실제 미분류와 아이콘 미지원은 구분한다.
6. 모바일 목록에는 40~48dp로 사용하고 업종명·등락률을 중심에 둔다. PC UI 개편이나 Android Gate 통과를 대신하지 않는다.

## 검토가 필요한 상징

- 전기전자/반도체: 현행 합성 분류가 매우 넓어 전자 모듈 상징이 반도체 의미를 충분히 담지 못할 수 있음.
- 원자력/에너지: 냉각탑은 원자력을 강조하며 전체 에너지를 대표하지 않음. 별도 에너지·전력기기 타일을 준비함.
- 통신/보안/서버: 서버 상징은 현행 합성 분류의 일부를 대표함. 미래 분류가 나뉘면 각각 확장 필요.
- 금융/은행, 제약/바이오, 건설/기계장비, 식품/유통: 현행 합성 항목용 상징이며 하위 산업을 대신 확정하지 않음.
- 국가·시장·레버리지·인버스·배당 등의 ETF 분류는 업종이 아님. 별도 폴더와 대응표로 관리함.
- 코스피200·코스닥150: 글자가 없는 시장 토큰 모티프이며 목록의 표시명이 식별을 보완함.

시스템 제안서는 설계 제안·미구현 상태입니다. 업종·테마 계약, 공급원, 분류체계, Gate 상태를 이 에셋 묶음으로 변경하지 않습니다.

검토용 HTML의 한글 글꼴은 한국어·라틴 문자 범위를 유지한 WOFF 서브셋으로 제공하며 라이선스는 `assets/FONT-LICENSE.txt`에 포함합니다.
