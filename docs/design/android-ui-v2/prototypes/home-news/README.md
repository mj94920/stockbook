# 모바일 홈·뉴스공시 독립 코드 프로토타입

PR #76의 승인 디자인을 토큰과 재사용 컴포넌트로 옮긴 코드 전달본이다. #76은 디자인 원본·미리보기 PR이고, 이 디렉터리는 별도 구현 검토본이다. 실제 Android 앱·Legacy PWA 복원이 아니며 Android Gate와 Shared Contract를 변경하지 않는다. 사용자 요청 범위는 홈·시장 뉴스공시 우선 구현과 나머지 화면 대조표다.

## 실행과 파일

`index.html`을 브라우저로 연다. 관리형 브라우저가 file URL을 차단하면 저장소 루트에서 `python -m http.server 8000 --bind 127.0.0.1`을 실행하고 해당 디렉터리의 index.html로 접근한다. 외부 CDN·설치·API 없이 동작한다.

- `tokens.css`: 승인된 모바일 라이트 디자인의 `--sb-*` 토큰. PC 전역 토큰을 덮어쓰지 않는다.
- `ui.css`: `.sb-card`, 카드 제목/목록/금액, 탭·필터·피드·문서·하단 도구 컴포넌트.
- `app.js`: 홈·뉴스 화면 렌더, 필터 초안/적용/복구, 공시 예시, 내부 기사 리딩과 브라우저 뒤로가기 및 검토 상태 전환.
- `news-data.js`: 승인 원본의 보관 기사 5건과 포함 사진. 최신 데이터·사용권 승인·수집 방식이 아니다.
- `check.py`: Python Playwright 자체 검증. `CHROMIUM_EXECUTABLE`로 시스템 Chromium 경로를 지정할 수 있다.
- `SCREEN-COMPARISON.md` / `.csv`: 요청한 8개 열의 22행 대조표, 대표본과 차이 기록.
- `source-manifest.json`: 첨부 ZIP의 승인/현재/일지 보완본 해시와 출처.
- `VALIDATION.md`: 작성자 검증과 시스템룸 미검수 상태를 구분한 결과.

하단 홈/시장으로 두 승인 영역을 이동한다. 시장 진입은 이번 프로토타입에서 뉴스공시를 열며 시황 자체를 구현한 것이 아니다. 카드의 시황·경제일정·종목·자산상세·일지·설정·인증·발견 목적지는 원래 의도를 유지하고 범위 밖 안내만 표시한다. 이들 화면을 새로 만들거나 뉴스로 대체 연결하지 않았다. 하단 고정 정책은 미결정이므로 현재 일반 문서 흐름에 둔다.

## 반영 범위와 경계

홈은 총자산/보유·관심종목/시장지수/투자신호/주요일정/일지초안의 6카드 순서다. 총자산은 원본 가상 KRW 예시에 예수금을 포함하고 금액에 원 단위를 붙인다. 해외·USD·통화 환산 기능을 추가하지 않는다. 관찰/메모·매수/매도/CSV 입력이나 예수금 상세/취소정정 화면은 없다. 비용 미확인을 0원으로 만들거나 AI 결과를 생성하지 않는다. 신호는 가상 예시이고 `규칙 판정 · 투자 권유 아님`을 유지한다.

뉴스는 일반 기사/공시를 나누고 언론사는 필터로만 사용한다. 전체 기사 피드를 날짜 최신순으로 정렬한다. 필터 선택은 적용 전까지 피드에 반영되지 않으며 공시 왕복·홈 왕복·브라우저 뒤로가기 때 유지한다. 기사 선택은 프로그램 안의 리딩 화면으로 연결한다. 본문은 미연결 상태이며 모든 문단이 검토용 설명 예시임을 표시한다. 목록으로 돌아갈 때 적용한 언론사 필터·스크롤·선택 기사 포커스를 유지한다. 언론사 원문은 리딩 화면의 별도 보조 링크로만 새 창에서 열고 `noopener noreferrer`를 사용한다. 자동 API 호출은 없고 CSP의 `connect-src 'none'`으로 차단한다. 사진은 원본에 내장된 data URI라 외부 다운로드가 없다. 외부 원문 사이트의 내용·가용성·재배포 권한은 검증하지 않았다. 공시 원문은 실제 링크 대신 가상 안내 토글이다.

검토 도구에서 가상 예시/미연결/로딩/오류/실제 결과 없음 상태를 각각 확인할 수 있다. 결과 없음은 시연 상태이며 실제 Provider 조회를 수행했다는 의미가 아니다. 실제 데이터 미수신을 0원이나 샘플 값으로 조용히 대체하지 않는다.

예수금 상세(당일/정산 예정), CSV, 취소·정정은 미구현이다. 후속 시안에는 `임시 · 계약 미확정`을 유지해야 한다. DC-1의 `{ settled, amount, pending } + asOf` 조건부 승인과 기존 basis, 결제일 미확인 처리/이관 compatibility 경계를 바꾸지 않는다. DC-2의 원 이벤트 참조 void + 신규 정정 이벤트/correctionOf 및 연결 일지 보존을 따른다. ledger_revision은 #64 v3 범위다.

## 시스템룸 읽기 전용 검수 요청

다음 항목을 이 코드 PR의 실제 파일에서 확인해 달라. 아래 작성자 점검은 시스템룸 승인이 아니다.

1. 예수금 상세/CSV/취소·정정 화면은 이번 코드에 없으며 후속 임시 표기 경계가 문서화돼 있는가.
2. 표시 금액에 원 단위가 있고 서로 다른 통화를 합산하지 않는가.
3. android/ 및 shared/ 생성·수정이 없는가.
4. PC 루트 index.html에 모바일 UI를 이식하지 않았는가.
5. 자동 외부 호출이 없는가. 사용자가 리딩 화면에서 별도로 선택하는 원문 링크와 자동 데이터 호출을 구분한다.

검수 결과를 받을 때까지 시스템룸 검수 완료로 기록하지 않는다. 자동 머지/queue/automerge 라벨을 설정하지 않으며 사용자가 최종 검토·머지한다.

## 뉴스 UX 정정 (2026-10-20 사용자 승인)

#76 자료의 외부 원문 이동 설명보다 최신 사용자 지시인 프로그램 내 리딩을 우선한다. 기사 본문을 수집하거나 실제 내용을 생성하지 않으며 검토용 본문만 사용한다. 이 정정은 뉴스 읽기 동작에 한정하고 기존 승인 레이아웃/계약 경계는 유지한다.
