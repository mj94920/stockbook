# 작은형님·큰형님 조건과 신호 표시

2026-10-29 KST. PR #94 병합 이후 사용자 추가 조건을 반영한다. 기존 가격 조건만의 초록 ▲를 작은형님·큰형님으로 나누고, SVG 확대 비율에 따라 납작해지던 기호의 크기를 CSS 픽셀로 유지한다.

## 계산

공통 가격식은 [기존 수식](../chart-entry/README.md)의 A/B(9·26·52, 과거 25봉), 종가 단순 226일선, BB(20/2) 세 OR 그룹 그대로다. `entrySignalSeries`는 이 가격 조건 계산용으로 유지하고 실제 표시에는 `entryTierSeries`의 추가 조건을 적용한다.

| 조건 | 작은형님 | 큰형님 |
| --- | --- | --- |
| 공통 가격식 | 모두 충족 | 모두 충족 |
| `avg(V,1)` | 2,000주 이상 | 70,000주 이상 |
| `amount` | 150 이상 | 5,000 이상 |
| 양봉 | `O < C` | `O < C` |
| 상승률 | `C >= C(1)*1.025` 또는 `C >= O*1.025` | 동일 |
| 226일선 기울기 | 추가하지 않음 | `avg(C(3),226) > avg(C(2),226) > avg(C(1),226)` |
| 최소 가격 이력 | 226봉 | 229봉 |

기울기는 현재값을 포함하지 않은 과거 3·2·1봉 전의 단순 226일선 비교다. 거래량은 해당 일봉 값이다. 원식에 없는 첫 봉만 표시·거래 주체 추정·그 밖의 조건은 추가하지 않는다.

## amount는 억원 단위로 확정

사용자가 `amount`의 단위를 **억원**으로 확정했다. 실제 공급자 거래대금은 원 단위이므로 작은형님은 15,000,000,000원(150억원), 큰형님은 500,000,000,000원(5,000억원) 이상인지 비교한다. 단위 선택과 단위 미확인 판정 보류를 제거했다. 설정과 범례에 두 금액을 그대로 표시한다.

이전 검토 단계에서 저장된 백만원 해석이나 미선택 값도 현행 계산을 바꾸지 않는다. 초기화·종목 변경·축소 일봉 모두 같은 고정 단위를 사용한다. 공급자 자료의 전체 날짜·가격·거래대금과 HTS 일치 여부까지 확인됐다는 뜻은 아니다.

## 실제 금액 범위

기존 KIS 일별 거래대금의 날짜와 가격 일봉 거래량이 정확히 맞는 값만 사용한다. 최근 최대 100거래일 한 번의 조회 범위를 확대하지 않는다. 미수신·실패·거래량 불일치 날짜는 판정 보류다. 종가×거래량이나 합성 금액을 운영 차트에 대입하지 않는다. 가격 차트는 부가 조회를 기다리지 않고 표시하며 고정 금액 기준·금액 수신 봉 수·판정 보류 수를 안내한다. 수급 fallback은 거래대금 대용이 아니다.

## 표시

- 작은형님: 고가 위 **보라색 아래 화살표**, 상세 14×16px·축소 10×12px.
- 큰형님: 고가 위 **금색 별**, 외접 반지름 8px. 두 조건이 맞으면 표시 중인 큰형님 하나를 우선한다. 큰형님을 숨기면 충족한 작은형님을 볼 수 있다.
- 신저가: 저가 아래 하늘색 **마름모** 10×10px.
- RSI: 고가 위 주황색 **원** 10×10px. 입장 신호와 동시에 발생하면 위로 분리한다.

배경색 1.5px 테두리를 두며 표시 신호에 필요한 가격 위아래 여백을 확보한다. 표시 가격 범위가 달라져도 십자선·그리기 좌표의 역변환은 같은 축을 사용한다. 밝은 테마에서는 더 진한 색으로 바꾸고 실제 SVG 배경 대비 3:1 이상을 검사한다. 새로운 테마 버튼은 추가하지 않는다. 신호별 선택·손바닥 커서·Del·실행 취소·복원·범례와 봉 정보가 연결된다. 옛 `entry` 숨김 설정은 두 새 신호 숨김으로 해석한다.

## 검증과 남은 확인

`verify.cjs`와 [결과](result.json)는 운영 HTML에 **합성 OHLCV·합성 KIS 형식 금액·모의 IPC**를 제공한 화면 검사다. 억원 단위는 사용자 확인값이며, 화면의 금액 자체는 합성 테스트 입력이다. [다크](dark-wide.png) · [라이트](light-wide.png) · [좁은 창](dark-tablet.png). 인증된 실거래대금이나 Windows 실기 증거로 취급하지 않는다.

전체 `npm test` 94개·정적 검사·기존 스모크를 통과했다. 자동 검사는 두 규모 경계·억원의 원 단위 환산과 종전 백만원 금액의 제외·양봉·상승률 양쪽 분기·과거 226일선 하락·미수신 보류·미래 봉 배제·신호 중복 우선순위·삭제/복원·주기 분리·종전 단위 설정 무시와 축소 적용·가로세로 비율·테마 대비·가격 높이 변경을 확인한다. [전체 검사 로그](npm-test.txt)를 따른다.

원본 HTS 전체 날짜·수치 대조, 이번 변경의 Windows Electron 실기와 새 NSIS 설치본 검사는 아직 확인하지 않았다. 월봉 피보나치·BinaryWaveMACD의 암호화 수식은 계속 보류한다. 병합·배포는 별도다.


## 모바일 중간 확인 및 데스크톱 실기 이월

사용자 요청에 따라 데스크톱 실기는 **2026-10-30**로 이월했다. [Windows 체크리스트](WINDOWS-CHECK.md)로 대상 브랜치와 실제 검사 SHA를 확인한다. 아직 사용자 Windows 통과로 기록하지 않는다.

[오프라인 미리보기](preview.html)는 운영 차트 CSS/JS를 한 파일에 넣고 합성 OHLCV·금액만 제공한다. 종목 선택은 합성 예시 하나로 한정하며 실제 계좌·인증·외부 시세를 호출하지 않는다. 사용자 기본 지표와 혼동하지 않도록 시작 시 이 예시에서만 신저가 3봉·RSI 2/60 단순 설정을 적용해 여러 모양을 함께 보여준다. 별도 모바일 앱 구현이나 실제 휴대폰 호환 보증이 아니다.

`build-preview.cjs`로 다시 만들고 `verify-preview.cjs`로 확인한다. [터치 검사 결과](preview-result.json)와 [390px 화면](phone-preview.png)은 로컬 HTTP로 문서를 읽은 뒤 오프라인 상태에서 가상 터치 신호 정보·수평선 그리기와 드래그 확대를 검사한 결과다. 외부 HTTP 요청과 브라우저 오류는 없었다. 이 환경은 브라우저의 file URL 직접 열기를 차단하므로 파일 직접 실행은 미확인이다.

이 검사에서 신호 선택 직후 봉 정보가 표시되지 않고 손을 떼면 정보가 사라지던 문제를 수정했다. 신호 선택 시 봉 정보를 표시하고 touch의 pointerleave에서는 유지하며 차트 밖을 누르면 닫는다. 기존 마우스 이탈 시 닫기는 유지한다.

과거 거래대금 범위 확대는 사용자 승인 후 [별도 후속 브랜치](../chart-trading-history/README.md)에서 진행한다. 이 페이지의 최근 100일 한계와 Windows 대기는 #95 당시 범위이며, 후속 작업도 실제 과거 수신·Windows 검증 전이다.
