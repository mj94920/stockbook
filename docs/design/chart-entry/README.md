# 일봉 세력 입장

일봉에서 수식 조건을 충족한 봉 아래에 초록 ▲가 뜬다. 종합·상세 차트에서 사용할 수 있고, 봉 정보에도 표시한다. 지표 표시에서 숨기거나 표시를 선택한 뒤 Del로 지우고 복원할 수 있다. 주·월·연봉에는 추가하지 않는다.

계산은 사용자에게 다시 받은 아래 세 조건을 전체 수식으로 사용한다. 이전의 거래량·거래대금·양봉·2.5%·226일선 기울기 조건은 포함하지 않는다. 별도 거래대금 조회가 실패하거나 늦어져도 가격 자료만으로 계산한다.

```text
A=(highest(high,9)+lowest(low,9)+highest(high,26)+lowest(low,26))/4;
B=(highest(high,52)+lowest(low,52))/2;

(crossup(C,A(25)) and crossup(C,B(25))
or
((H>A(25)) and (H>B(25))))
and
(crossup(avg(C,1),avg(C,226))
or (C>avg(C,226)))
and ((Crossup(H,BBandsup(20,2)))
or (O>(BBandsup(20,2))))
```

A(25)·B(25)는 25봉 전의 값이다. Crossup은 이전 값이 이전 기준 이하이고 현재 값이 현재 기준을 엄격히 넘는 경우다. 226일선은 종가 단순평균, BB는 최근 종가 20개의 모집단 표준편차 2배 상단이다. 기존 차트의 BB 40/1.9 +25봉 표시와는 다른 고정 수식이다. 지표 설정의 표시용 이평·구름·BB 기간을 바꿔도 이 수식 상수는 바뀌지 않는다.

최소 226개 일봉이 있어야 판정하고 이력 부족은 빈 값으로 둔다. 전체 수신 이력에서 계산해 보이는 구간만 자르므로 확대·이동으로 기준이 바뀌거나 미래 봉으로 과거 신호가 바뀌지 않는다. 마지막 미완성 봉의 판정은 수신 자료에 따라 달라질 수 있다. 실제 매매 주체를 확인한 데이터로 해석하지 않는다.

## 검증

전체 `npm test` 92개·정적 검사·기존 스모크 통과. 226봉 준비 기간, 두 BB 분기, 세 논리 그룹, 정확한 25봉 참조, 미래 자료 배제, 부가 금액 대기 중 표시, 삭제·복원, 이동·확대·주기 제한 및 종합 표시를 확인했다.

`live-result.json`은 실제 네이버 응답의 해시·수신 시각과 해당 날짜 계산값이다. `browser-result.json`과 PNG는 이 실제 수신 가격을 모의 IPC로 제공한 운영 HTML의 화면 검사다. 합성 자료를 쓰는 Node/브라우저 회귀 검사와 구분한다. Windows Electron/NSIS의 이번 신호 실기는 미실행이다.

재검증은 `node docs/design/chart-entry/verify-live.cjs`로 공개 가격 자료를 받아 `/tmp/stockbook-entry-live-data.json`에 준비한 뒤 `node docs/design/chart-entry/verify-browser.cjs`를 실행한다. 새 수신값이 과거 관측값과 다를 수 있으며 원자료 차이는 별도로 기록한다. 앱에 별도 수집·저장·인증·API 경로를 추가하지 않는다.
