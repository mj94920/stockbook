# 과거 거래대금 수동 추가 조회

2026-10-29 KST. 사용자 승인에 따라 최근 100거래일의 거래대금만 받던 경로에 날짜 구간별 추가 조회를 붙였다. PR #95의 `8101626030db89834e7e0b2ece19ed9c10023ac2`에서 분기한 **codex/chart-trading-history** 작업이며 #95 브랜치는 변경하지 않는다. 후속 PR은 #95에 의존하며, #95 병합 뒤 main과 동기화해 이 변경만 검토한다.

## 사용

- 상세 **일봉 → 거래대금**에서 `과거 거래대금 불러오기`를 누른다.
- 종합 축소 일봉에서는 **차트 도구** 안에 같은 버튼이 있다. 거래대금 구간에 버튼을 늘려 가격·거래량 비율을 밀어내지 않는다.
- 현재 표시한 개월 수와 별개로 **이미 받은 일봉 이력 최대 1,000봉**까지 조회한다. 기존 최근 조회 결과를 먼저 재사용한다.
- 진행 중에는 수신·거래량 일치·판정 보류 수와 추가 요청 횟수를 표시하고 `추가 조회 취소`를 제공한다. 가격·그리기·확대는 계속 작동한다.
- 일부 날짜만 받았거나 실패·취소된 경우에도 받은 금액을 유지한다. 기간을 바꾸면 현재 뷰의 추가 요청을 멈추고 받은 과거 자료를 재사용한다. 다시 버튼을 눌러 이어받을 수 있다.
- 날짜와 가격 일봉 거래량이 정확히 맞는 금액으로 작은형님 **150억원**·큰형님 **5,000억원** 신호를 재계산한다. 누락·거래량 불일치는 계속 보류한다.

## 공식 규격과 요청 경계

KIS 공식 [국내주식기간별시세 예제](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/inquire_daily_itemchartprice/inquire_daily_itemchartprice.py)의 1회 최대 100건·시작일/종료일 인자를 확인했다. 가장 이른 수신일의 전날로 다음 종료일을 옮기며 휴일·월말·연말도 UTC 날짜 계산을 사용한다. API가 모든 과거 날짜를 제공한다고 보장하지 않는다.

기존 메인 인증과 고정 HTTPS 경로 `/uapi/domestic-stock/v1/quotations/inquire-daily-itemchartprice`, TR `FHKST03010100`, 시장 **J/KRX**, 주기 **D**, 원주가 **1**을 유지한다. 임의 호스트·시장·헤더·TR을 렌더러에서 받지 않는다. API 키는 메인 프로세스에 남는다.

- 첫 자동 조회는 기존처럼 최근 최대 100행 한 번이다. 추가 순회는 버튼을 눌렀을 때만 시작한다.
- 한 번의 작업에서 **추가 묶음 요청 최대 10회**, 결합 대상 최대 1,000봉이다. 기존 최근 묶음을 재사용하므로 정상적인 100행 응답이면 최대 9회 추가로 1,000봉에 도달한다. 적은 행이나 누락 때문에 도달하지 못하면 부분 수신으로 남는다.
- 범위 요청 사이 최소 간격 500ms를 둔다. 페이지별 메인 제한 8초·렌더러 대기 9초·전체 작업 제한 45초를 적용한다. 큐에서 시간이 초과된 요청은 나중에 HTTP를 보내지 않는다.
- 페이지의 100행 상한은 유지한다. 결합된 입력만 1,000행까지 허용한다. 종목·날짜·중복·범위·안전 정수 원 금액·거래량을 검증한다.
- 빈 응답·진전 없는 응답·잘못된 응답·요청 실패·시간/횟수 상한에서 중단하고, 부분 자료를 전체 성공으로 표시하지 않는다. 범위 끝까지 조회했더라도 날짜/거래량이 부족하면 보류 수를 남긴다.
- 같은 렌더러의 동일 범위 작업은 구독을 공유한다. 한 뷰를 취소해도 다른 구독 뷰가 계속 조회할 수 있다. 메인 페이지 캐시도 같은 종목/기간의 진행 요청을 합친다.
- 종목·기간·주기 전환, 화면 정리, 창 종료 시 해당 구독의 후속 요청을 멈추고 늦은 응답을 적용하지 않는다. 이미 메인에서 시작된 한 묶음은 자체 제한 안에서 끝날 수 있으며 UI 취소가 즉시 모든 HTTP를 중단한다는 뜻은 아니다.
- 캐시는 메모리 60초·최대 20개 항목으로 제한한다. 페이지 캐시 키는 종목·조회 범위를 포함한다. DB 저장·폴링·장기 자동 수집은 추가하지 않는다.

## 검증

단위·브라우저 검사는 다중 페이지 날짜 경계·정수 금액·요청/행 수 제한·빈 응답/오류/중복/반복·타임아웃·취소·지연 응답·부분 결과·범위별 캐시·같은 작업 구독·기간 전환 보존·IPC 프레임과 날짜 검증·패키징을 포함한다. 전체 `npm test` 105개·정적·스모크를 통과했다. 최종 IPC 범위 전달 추가 확인도 [단위 재검사 11개](unit-recheck.txt)로 통과했다. [전체 로그](npm-test.txt)를 따른다.

[화면 검사 결과](result.json)는 운영 HTML에 **합성 OHLCV와 합성 KIS 형식 금액을 모의 IPC로 제공**한 것이다. 400봉 중 최근 100봉만 받은 상태에서, 추가 3묶음으로 400봉이 연결되고 2024-08-27의 과거 큰형님 신호가 생기는 것을 확인했다. [이전](before.png) · [200봉 수신 중](partial.png) · [400봉 완료](complete.png) · [축소 차트 도구](compact-tools.png).

[독립 미리보기](preview.html)도 합성 자료다. 100봉 상태에서 버튼을 누르면 세 묶음을 시간차로 모의 수신한다. [840px 가상 터치/오프라인 결과](preview-result.json)는 외부 요청 없이 번들 문서를 확인한 결과이고 실제 모바일 앱 검증은 아니다. 빌드는 `node docs/design/chart-trading-history/build-preview.cjs`, 검사는 `verify.cjs`와 `verify-preview.cjs`를 사용한다.
