## 2. 직접 실행하기

### 필요한 것

- 일반 웹 브라우저
- Python 3
- 이 폴더의 HTML·JavaScript·JSON 파일 전체

화면을 열기만 할 때 Node.js, Playwright, 증권계좌, API 키, Firebase 계정은 필요하지 않습니다. GitHub의 HTML 파일 보기만으로는 차트가 실행되지 않습니다.

### 파일 하나로 열기

`playground.html`에는 코드와 자료가 모두 들어 있습니다. 내려받은 뒤 Chrome/Edge로 열어 조작할 수 있습니다. 관리 정책이 로컬 파일 열기를 차단하는 환경이라면 아래 HTTP 실행 방법을 사용합니다. 이 클라우드에서는 직접 파일 열기가 차단되어 같은 HTML을 내부 HTTP로 제공해 조작을 검증했습니다.

### 실행 순서

1. 브랜치 `codex/chart-proof-20261022`를 내려받습니다. 이미 다른 작업을 하는 저장소라면 그 작업을 먼저 보존합니다. 전체 저장소 ZIP을 받아 별도 폴더에 풀어도 됩니다.
2. 터미널을 열고 `docs/design/desktop-chart-proof/2026-10-22` 폴더로 이동합니다.
3. 아래 명령으로 파일 제공 서버를 실행합니다.

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

Windows에서 `python3` 명령이 없고 Python 런처가 설치되어 있다면 다음 명령을 사용합니다.

```powershell
py -3 -m http.server 8000 --bind 127.0.0.1
```

4. 같은 컴퓨터의 브라우저 주소란에 `http://127.0.0.1:8000/styled-chart.html`을 입력합니다. 이 주소는 내부 실행용이며 다른 사람에게 전달할 공개 주소가 아닙니다.
5. 검토가 끝나면 서버를 실행한 터미널에서 `Ctrl+C`로 종료합니다.

HTML 파일을 더블클릭해서 직접 열면 브라우저가 JSON 읽기를 차단할 수 있습니다. 서버는 위 실험 폴더에서 실행하세요.

## 차트를 가리키고 선 그리기

차트 위로 마우스를 옮기면 날짜·가격 십자선이 나타납니다. 봉 위치에서는 당일 가격·거래량·이동평균값을 함께 봅니다. 가격 차트와 같은160봉 축인 거래량·A/D 영역도 날짜선이 연결됩니다. 5일 확대 수급은 같은 날짜 자료가 있을 때만 연결합니다. 미래25봉 빈 공간에는 실제 봉 정보를 만들지 않습니다.

- **추세선:** 시작점과 끝점을 차례로 누릅니다.
- **수평선:** 원하는 가격을 한 번 누릅니다.
- **봉중심선:** 고가·저가 중심 또는 시가·종가 중심을 고르고 봉을 누릅니다. 그 봉의 중앙 가격에 수평선을 그립니다.
- **3등분선·4등분선:** 가격 범위 두 끝을 누르면 경계와 내부 등분선을 표시합니다.
- **사각형·타원:** 범위의 두 모서리를 누릅니다.
- **화살표:** 시작점과 끝점을 누릅니다.
- **펜:** 마우스를 누른 채 그립니다.
- **선택·십자선:** 그린 선의 몸체를 끌어 전체를 이동하고, 끝점 손잡이를 끌어 모양을 수정합니다. 선을 선택하고 **선택 삭제**로 지울 수 있습니다.
- **봉중심선 이동:** 좌우로 옮겨 다른 실제 봉의 중앙 가격에 맞춥니다.
- **취소:** 그리거나 옮기는 도중 **Esc**를 누릅니다. 이동 취소는 시작 전 좌표로 되돌립니다.
- **저장·불러오기:** 현재 브라우저에 선을 저장하고 복원합니다. 화면을 새로 열면 불러오기를 눌러 복원합니다. 다른 PC나 서버와 공유되지 않습니다.

선은 날짜와 가격에 고정됩니다. 테마·창 크기·가격축 범위가 바뀌어도 같은 좌표로 다시 그립니다. 현재 화면 밖 날짜의 저장 자료나 잘못된 자료를 불러오면 현재 선을 유지하며 오류를 알립니다. 브라우저 데이터를 지우면 저장한 선도 없어질 수 있습니다.

봉중심선은 고가·저가 중앙을 기본으로 두고 몸통 중앙을 선택할 수 있습니다. RSI·ATR·OBV·일반MACD는 제안 단계입니다.

## 4. 가격 차트 읽는 법

실제 수신 일봉 1,000개로 계산하고, 화면에는 최근 160개를 표시합니다. 봉의 시가·고가·저가·종가는 수신값을 사용합니다. 종가가 시가 이상이면 빨강, 시가보다 낮으면 파랑이며 보합도 빨강에 포함합니다.

### 가격 이동평균선

현재 계산 방식은 모두 **종가의 단순이동평균**입니다.

| 기간 | 다크 모드 색상 | 굵기 |
|---|---|---|
| 5일 | 연분홍 | 기본 |
| 10일 | 하늘색 | 기본 |
| 20일 | 노랑 | 조금 굵게 |
| 60일 | 초록 | 기본 |
| 120일 | 회색 | 기본 |
| 200일 | 빨강 | 굵게 |
| 350일 | 황갈색 | 기본 |
| 480일 | 보라 | 기본 |

라이트 모드는 같은 계열의 더 진한 대비색을 씁니다. 5일선이 10일선 위면 두 선 사이를 연분홍, 아래면 하늘색으로 채웁니다. 이는 선의 상대 위치이며 실제 투자자별 매매나 확정된 매수·매도 신호가 아닙니다.

### 민트색 BB 상한 점선

사용자가 제공한 수식은 다음과 같습니다.

```text
A = shift(BBandsUp(period,D1),midPeriod-1);
period = 40, D1 = 1.9, midPeriod = 26
```

실험본은 `40일 종가 평균 + 1.9 × 40일 종가의 모집단 표준편차`를 계산하고 오른쪽으로 25봉 옮깁니다. 중심선·하한선은 표시하지 않습니다. 영웅문의 BBandsUp 및 shift와 수치 일치 여부는 별도 대조가 남았습니다.

오른쪽의 빈 25봉 공간에 선이 이어지는 것은 과거 계산값의 이동 표시입니다. 미래 가격 예측이나 미래 가격 자료가 아닙니다. 빈 공간에 실제 캔들·거래량을 만들지 않습니다.

### 수식 1~3 기준선 비교

최근 600봉에 첫 봉부터 1, 2, 3… 번호를 부여하고, 540·580·595번째 봉의 종가를 수평선으로 표시합니다. 현재 자료에서는 각각 2026-07-23의 270,000원, 2026-09-18의 260,000원, 2026-10-15의 207,500원입니다.

이는 고정된 600봉 가정입니다. 항상 현재 기준 60·20·5일 전 가격을 계산하는 일반 공식으로 사용하면 안 됩니다. 영웅문에서 sum(1)이 어느 범위부터 누적되는지 확인해야 합니다.

## 5. 거래량·매매세: 한 칸으로 읽기

바깥의 넓은 막대와 안쪽의 좁은 막대는 같은 날짜, 같은 바닥에 겹쳐 있습니다.

| 표시 | 의미 |
|---|---|
| 바깥 빨강 | 거래량이 직전 20거래일 평균 이상 |
| 바깥 하늘색 | 거래량이 직전 20거래일 평균 미만 |
| 바깥 막대 높이 | 당일 거래량 |
| 안쪽 노랑 | 종가 위치로 계산한 양의 매매 압력 |
| 안쪽 검정 | 종가 위치로 계산한 음의 매매 압력 |
| 안쪽 막대 높이 | 매매 압력의 절댓값 |

거래량 평균에는 오늘 거래량을 넣지 않습니다. 과거 20개가 없으면 많음·적음 판정 없이 중립색을 씁니다.

```text
종가 위치 = (2×종가 − 고가 − 저가) ÷ (고가 − 저가)
당일 매매 압력 = 종가 위치 × 거래량
```

고가=저가면 압력은 0입니다. 종가가 고가에 가까우면 양수, 저가에 가까우면 음수입니다. 양수·음수 막대를 모두 위로 겹치므로 부호는 색으로 구분합니다.

이것은 일봉으로 만든 **추정 지표**입니다. 실제 매수·매도 주도 체결량이나 암호화된 영웅문 원수식의 계산 결과가 아닙니다. 외국인·기관·개인을 구분하지 못합니다.

## 6. 거래대금: 현재 빈 영역

현재는 칸과 아래 범례만 있습니다. 실제 날짜별 거래대금을 확보하지 못해 막대를 그리지 않았습니다. 종가×거래량을 실제 거래대금으로 대체하지 않았습니다.

향후 적용할 구간은 다음과 같습니다. 막대 높이는 거래량, 색상은 실제 거래대금 구간입니다.

| 실제 거래대금 | 다크 모드 색상 |
|---|---|
| 300억원 미만 | 숨김 |
| 300억원 이상~500억원 미만 | 파랑 |
| 500억원 이상~1,000억원 미만 | 연두 |
| 1,000억원 이상~3,000억원 미만 | 주황 |
| 3,000억원 이상~5,000억원 미만 | 빨강 |
| 5,000억원 이상~1조원 미만 | 연보라 |
| 1조원 이상 | 흰색 |

사용자 수식의 분대금() 정의와 금액 단위 대조도 남았습니다. 범례가 보인다는 사실은 실제 금액 자료가 연결됐다는 뜻이 아닙니다.

## 7. A/D: 노란 누적 추정선

2022-09-16부터 수신된 1,000봉 전체의 당일 매매 압력을 누적하고 최근 160봉 구간을 보여줍니다. 해당 기간 시작 전 누적값은 0으로 둡니다.

```text
오늘 A/D = 어제 A/D + 오늘 매매 압력
```

시작일을 바꾸면 누적값도 달라집니다. M 표시는 가중 거래량 백만 단위이며, 실제 보유 주식 수·보유율이 아닙니다. 가격 차트에서 하락하는 날에도 A/D가 올라갈 수 있습니다. 이 계산은 종가의 전일 대비 상승 여부가 아니라 당일 고가·저가 사이의 위치를 사용하기 때문입니다.

특정 주체가 매집했다고 판단하는 용도로 단독 사용하지 마세요. 실제 개인 매수가 많아도 A/D는 상승할 수 있습니다.

## 8. 외국인·기관·개인: 실제 순매수 누적

이 영역은 앞의 A/D와 달리 공급자가 보고한 실제 투자자별 일별 순매수 수량을 각각 사용합니다.

| 색상 | 투자자 |
|---|---|
| 노랑 | 기관 |
| 분홍 | 외국인 |
| 남색 | 개인 |

현재 확보한 기간은 **2026-10-15~2026-10-21, 5거래일**입니다. 첫날 직전 값을 0으로 두고 첫날 순매수를 포함해 누적합니다. 양수는 이 기간의 순매수, 음수는 순매도입니다.

| 투자자 | 5거래일 누적 |
|---|---:|
| 외국인 | -1,275,121주 |
| 기관 | -1,546,172주 |
| 개인 | +2,316,914주 |

기타 투자자 등이 있으므로 세 주체의 합계가 반드시 0은 아닙니다. 개인을 외국인·기관 수량의 차액으로 추정하지 않았습니다. 없는 날짜나 오늘 자료를 0으로 채우지도 않았습니다.

**이 칸은 5일 확대축, 가격·거래량·A/D는 160봉 축입니다.** 같은 가로 위치라고 같은 날짜로 읽지 말고 각 칸의 날짜를 확인하세요. 원본 영웅문과 모양을 비교하려면 같은 종목·기간·단위·계산 시작점을 맞춰야 합니다.

이 값으로는 최근 누가 순매수했는지를 비교할 수 있습니다. 누가 현재 몇 %를 보유하는지는 알 수 없습니다. 시작 전 보유량을 모르므로 누적 순매수를 총보유량으로 해석하면 안 됩니다.

## 9. 데이터와 아직 안 되는 것

- 일봉은 삼성전자 공개 시세 스냅샷, 수급은 네이버 integration 응답입니다. 계좌정보나 API 키가 없습니다.
- 마지막 일봉은 2026-10-22 장중 자료입니다. 확정 종가로 해석하면 안 됩니다.
- 공급자 응답 간 가격 차이가 관찰되어 거래소·수정주가·갱신 기준 대조가 남아 있습니다.
- 제품 앱의 Electron IPC·저장·실시간 갱신은 연결하지 않았습니다.
- 기관·개인·외국인 실제 보유량/보유율은 이 실험에서 구현하지 않았습니다.
- BinaryWaveMACD, 신저가, 과매도, ‘세력 입장’ 신호는 미구현입니다. 제공된 원수식과 미확인 항목은 [USER-FORMULAS.md](USER-FORMULAS.md)에 보존했습니다.
- 개발 가능한 것과 구현 완료된 것은 다릅니다. 암호화된 원지표와 같다고 검증한 결과도 아닙니다.

## 10. 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| 차트가 비어 있음 | 파일 더블클릭 대신 위 HTTP 서버로 실행했는지, HTML·JS·JSON이 모두 같은 폴더에 있는지 확인 |
| 서버는 뜨는데 파일을 못 찾음 | 서버를 시작한 현재 폴더와 styled-chart.html 경로 확인 |
| 8000 포트가 이미 사용 중 | 서버 명령의 8000을 8001 등으로 바꾸고 브라우저 주소도 같은 포트로 변경 |
| 거래대금 막대가 안 나옴 | 현재 미구현이므로 정상. 범례만 제공 |
| 수급선이 가격 차트와 날짜가 다름 | 수급 5일 확대축과 가격 160봉 축을 사용하므로 화면 설명대로 확인 |
| 새로고침해도 시세가 그대로임 | 동봉 스냅샷을 읽는 실험본이므로 정상 |
| 수급 표시 실패 문구가 나옴 | investor-snapshot.json 존재·형식 확인. 누락값을 0으로 바꾸지 말 것 |

## 11. 개발자용 검증과 재개

Python 서버 실행에는 npm 설치가 필요하지 않습니다. 자동 검증만 Node.js와 Playwright를 사용합니다. 설치·검증 명령은 [README.md](README.md)를 참고하세요.

우선 재개할 순서는 날짜별 실제 거래대금 확보, 장기 수급 확보, 영웅문 BB/MA 수치 대조, 가격 기준 대조, 제품 연결입니다. 구현 전 실제 데이터와 추정 계산의 표시를 계속 구분해야 합니다.
