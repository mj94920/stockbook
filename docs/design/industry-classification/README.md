# 종목코드 기준 시장 업종 연결

사용자 결정: ETF·ETN·ELS 등 금융상품은 업종 분류에서 제외. 먼저 실제 시장 업종 자료를 연결하고, 종목명 정규식 추정으로 누락을 숨기지 않는다.

## 원본과 범위

- 원본: [네이버 업종 목록](https://m.stock.naver.com/api/stocks/industry?page=1&pageSize=100), 업종별 `/api/stocks/industry/{code}?page=N&pageSize=100`.
- 수집: 2026-11-06 KST. 79개 분류, 4,425개 증권, 원본 보고/수신 건수 일치·중복 0·실패 0. 상세 `source-summary.json`.
- 제외: ETF 1,184 + ETN 363 + ‘기타’에 포함된 펀드성 X클래스 2종목 = 1,549개. `stock` 원문 유형만으로 기업이라고 단정하지 않는다.
- 적용: KOSPI 938 + KOSDAQ 1,831 + KONEX 107 = **2,876개 주식·78개 업종**. 일반주/우선주를 각각 종목코드로 센다. 기업 수와 같다는 뜻은 아니다.
- ELS/ELW/DLS/FUND 등의 명시 상품 유형도 실행 시 제외한다. 제외 목록에 있는 상품은 원문 유형이 stock으로 들어와도 다시 추가하지 않는다.

## 데이터와 화면

`src/desktop/industry-data.js`는 공개 업종 ID·업종명·종목코드·종목명·시장과 출처/기준일만 포함한다. 개인 계좌, API 키, 보유량, 거래내역, 시세는 포함하지 않는다.

`themes.js`는 이 원본으로 분류한다. 기존 종목명 키워드·직접 입력 업종 문자열로 업종을 새로 추측하지 않는다. 코드가 원본에 없으면 ‘분류 확인 필요’로 표시한다. 상위 **17개 업종군은 앱 탐색용 묶음**이며, 원본이 제공한 공식 상하위 계층이라고 표시하지 않는다. 하위 항목은 원본의 78개 업종명을 그대로 쓴다.

시가총액 제한이 있는 기존 시세 목록과 업종 구성원을 분리했다. 시세를 못 받은 소형주도 업종 목록에서 누락하지 않는다. 업종 기본 목록 전체에 받은 시세만 코드로 결합하며, 시세 미수신 종목의 가격·등락률은 `-`로 표시한다. 예를 들어 반도체는 원본의 173종목(일반 stock 표기 169 + KONEX 4)을 모두 제공한다.

기존의 두 선택 상자 배치를 유지하고 업종군 → 원본 업종 → 종목을 탐색한다. 검색·페이지 이동·뉴스 화면 유지·관심 추가를 재사용한다. 관심 추가 시 화면 이름 SECTOR가 아니라 실제 시장을 저장한다.

## 한계와 갱신

- 이는 네이버 원본 기준 스냅샷이며 KRX 공식 상장 목록 전수 대조 결과가 아니다. KRX 원문은 환경의 허용 호스트 제한으로 조회가 차단됐고 재시도/우회하지 않았다.
- 업종 분류는 기준일 이후 신규 상장·사명 변경·재분류를 자동 반영하지 않는다. 화면에 기준일을 표시하며, 새 종목은 원본 미확인으로 남긴다. 주기적 갱신 파이프라인은 별도 작업이다.
- 사업 분야(설계·장비·소재 등) 및 투자 테마는 원본 업종과 별개다. 근거가 없는 더 세밀한 사업 분류를 확정한 것으로 표시하지 않는다.
- 기존 KOSPI/KOSDAQ 시세 제공 API의 수집 제한 자체는 바꾸지 않았다. 업종 목록은 이 제한으로 잘리지 않는다.
- Windows 실기 검증, 병합, 배포는 별도다. EXE 빌드를 실행하지 않았다.

## 검증

원본 78개 업종 전부 연결, 2,876종목/시장별 수·173개 반도체 연결, ETF/ETN/ELS 및 원본 오표기 펀드 제외, 잘못된 종목명이나 업종 문자열에 의한 오분류 방지, 신규 종목 분리, 시세 없는 종목의 빈 표시, 코드 중복 제거, 검색/페이지 이동, 실제 시장으로 관심 추가, 뉴스 화면 유지, 패키징·렌더러 파일 복사를 검사한다.

## 재현 절차

`collect.py`는 공개 업종 목록과 구성원을 다시 수집하며, 파일이 있는 디렉터리에 감사 JSON/CSV를 저장한다. `export.py SOURCE_DIRECTORY`는 검토한 2026-11-06 기준 건수와 일치하는 자료만 런타임 스냅샷으로 내보낸다. 미래 갱신 시 변경된 건수·상품 종류를 재검토한 뒤 이 제한도 의도적으로 갱신해야 한다. 자동 배포·주기 작업으로 실행하지 않는다. Python 표준 라이브러리와 curl만 사용한다.
