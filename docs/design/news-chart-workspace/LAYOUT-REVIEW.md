# 종합 화면 차트 우선 배치 검토

2026-10-27 KST. 기준 #92 `40d55160213b4813d3271d439e67ad1dfe34b38d`.

사용자 화면에서 차트는 작고 매매패널 아래에 빈 공간이 남았다. 기존 행 비율 0.65:1.35를 없애고 차트가 남는 높이를 받도록 했다. 하단은 내용 높이를 쓰되 화면 높이의 44%·480px 중 작은 값으로 제한해, 넘는 입력·목록은 내부에서 스크롤한다. AI/신호는 설명 길이로 부모 행의 높이를 늘리지 않고 각 영역이 스크롤한다. 투자일지는 별도 비율로 넓게 유지한다. 지표·데이터·일봉/주봉/월봉 로직은 변경하지 않았다.

## 브라우저 측정

수치는 매매 탭, 기본 배율의 보존 삼성전자 데이터 기준이며 캔들+거래량 호스트 높이다. 실제 시세·계좌 캡처가 아니다.

| 화면 | 차트 변경 전 → 후 | 매매 영역 변경 전 → 후 |
| --- | --- | --- |
| 2560×1440 | 275 → 700px | 905 → 480px |
| 1600×900 | 99 → 244px | 541 → 396px |
| 1024×768 | 79 → 170px | 429 → 338px |

같은 2560×1440에서 예수금 탭의 차트는 916px, 투자일지의 작업 영역은 805px다. 매매의 목표/손절 입력은 스크롤 후 포커스할 수 있다. 긴 분석 문단을 삽입해도 차트 높이가 바뀌지 않고 분석 영역 안에서 스크롤됨을 확인했다. 잔고·매매·계산기·일지·거래내역·실현손익·예수금 전환 및 라이트/다크 전환에 pageerror는 없었다.

## 검사 결과와 CI 주의

- 정적 검사, Node/브라우저 검사 30건, 전체 스모크 통과. Node 22.23.3 / Playwright 1.56.0 / 시스템 Chromium 154.
- 초기 실행에서는 기존 스모크의 `차트 높이 < 전체 40%` 조건 때문에 실패했다. 현재 사용자 요구와 반대인 이 조건을 `차트 높이 >= 전체 40% 및 작업 영역 >= 180px`로 바꾸고, 긴 분석의 독립 스크롤·짧은 작업의 높이 회수·투자일지 확장을 추가로 검사한다. 정렬·겹침·하단 잘림·기능·입력 보존 검사는 유지했다. 검토 화면은 기존 1400·1024에 2560·1600을 추가했다.
- `scripts/smoke.mjs` 변경이 포함된다. AGENTS.md/CLAUDE.md에 따라 사람이 검사 변경을 검토하고 `tests-approved` 라벨을 붙여야 CI가 PR 브랜치의 새 검사를 사용한다. 기존 main 검사의 예전 높이 제한으로 실패하는 결과를 제품 회귀로 혼동하지 않는다. 라벨은 자동으로 붙이지 않았다.
- Windows Electron/NSIS 실기 및 배포는 실행하지 않았다. #85 선행 확인·사용자 승인과 각 PR의 별도 병합 승인 조건은 유지한다.
