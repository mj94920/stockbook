# 기존 판정 동등성을 먼저 통과한 조건식 구조 이관

기준: `codex/indicator-screening`의 `f435fbc48767cbb87fa08161027655979d16fe78`. 사용자 지시에 따라 먼저 기존 조건식의 결과 동등성을 확인하고, 그 검증 통과 후 조건별 시간 설정과 중첩 논리를 연결했다.

카탈로그 접수·파일 간 대조는 완료로, 현행 영웅문4 전체 목록 대조·계산 동등성은 미완료로 유지한다. K0150-###는 자료 관리용 ID이며 이번 실행 구조의 조건 식별자로 사용하지 않는다. 623행을 실행 지원 목록으로 등록하지 않았다.

## 1차 통과 기준과 증거

`test/fixtures/screener-v1/`에 기준 커밋의 엔진과 공유 시계열 모듈을 바이트 그대로 보존했다. `provenance.json`에 커밋과 파일 해시가 있고 검사가 이를 확인한다. 운영 코드는 이 복사본을 사용하지 않는다. 현재 코드 두 개를 비교해 같은 버그를 숨기는 방식 대신 고정된 이전 구현을 비교 기준으로 쓴다.

`src/screener/engine.js`에서 기존 계산과 봉 선택을 공용 평가 함수로 분리했고, `expression.js`의 이관 어댑터가 기존 평면 AND/OR 조건을 버전 2 문서로 변환한다. 1차에서는 조건별 다른 주기·봉전이나 NOT를 화면에 연결하지 않았다.

- **3,796개 입력 조합**에서 이전 엔진과 이관 어댑터의 반환 객체 전체가 일치했다. 충족/미충족/판정 불가뿐 아니라 기준일·봉 상태·실제/기준/직전 값·이유·출처까지 비교했다.
- 비교 축: 짧은 이력·충분한 이력·긴 연봉 이력, 6개 기존 지표, 비교/상하향 돌파/일목 판정, 4개 봉 주기, 완성·최신, AND·OR, 마지막 봉 완성 여부, 실제 거래대금 수신/미수신/거래량 불일치.
- 직전 이평 값이 같으면 현재 위/아래로 갈 때 기존의 ≤/≥ 돌파를 유지한다. 키움 문서의 엄격 부등호로 바꾸지 않았다.
- 4개 봉에서 완성 기준으로 한 봉 물러나면 돌파용 직전 장기 이평이 부족해 판정 불가가 된다. 동일값 5개 봉 사례에서는 이력이 충분해 미충족이 된다. 두 경우를 각각 보존했다.

확장 전 실제 검사 기록은 [gate1-before-extensions.tap](gate1-before-extensions.tap)에 있다. 3개 검사 통과를 확인한 뒤 2차 구현을 시작했다. 현재 차등 검사도 이 기준을 계속 실행한다. 2차의 새 실행기도 동일 입력에서 같은 상태·기준일·수치·봉 상태를 내는지 함께 비교한다.

## 2차 연결

기존 `StockBookScreener.evaluate`의 평면 API는 유지한다. 화면에서는 기존 입력을 구조화된 문서로 옮겨 `StockBookScreenExpression.evaluateExpression`으로 평가한다. 기존 화면에는 조건식 영구 저장 기능이 없었으므로 이번 이관은 실행 전의 입력 변환이며, 사용자 저장 DB를 바꿨다는 뜻은 아니다.

문서는 버전 2, 최대 12개 조건 정의, 논리 트리로 구성된다. 각 조건은 A~L 식별자, 기존 지표 매개변수, `time: {cycle, mode, barsAgo}`를 가진다. 트리는 참조·AND·OR·NOT이며 원본 설명이나 사용자 문자열을 eval로 실행하지 않는다. 이 식별자는 문서 안의 참조이고 키움 공식 항목 ID가 아니다.

- **조건별 주기·기준·봉전:** 공통 설정을 상속하거나 각 조건의 일/주/월/연봉 및 완성/최신을 선택한다. 0~1,200봉전은 선택한 기준봉에서 뒤로 센다. 음수·소수·미래 참조는 거부한다.
- **완성 0봉전과 최신 0봉전:** 마지막 봉이 미확정이면 완성 0은 최신 1이다. 완성 1은 최신 2다. 공급자가 마지막 일봉 완성을 명시하면 완성 0과 최신 0이 같다. 주·월·연봉은 기존처럼 마지막 집계를 미확정으로 취급한다. 거래 달력에 근거한 새 종결 판정을 도입하지 않았다.
- **중첩 논리:** 비워 두면 기존 AND/OR를 적용하고, 입력하면 `(A OR B) AND NOT C`처럼 참조한다. 우선순위는 NOT → AND → OR, 괄호가 우선한다. 빈 그룹·없는 참조·과도한 깊이·실행 코드 문자열은 거부한다.
- **3값 논리:** NOT(판정 불가)는 판정 불가다. AND에 미충족이 있으면 미충족, OR에 충족이 있으면 충족이 되며 나머지 미확인 조건의 결과도 보존한다.
- **평가 흔적:** 조건별 실제 기준일·주기·최신/완성·봉전과 실제/기준/직전 값을 남긴다. 서로 다른 주기의 결과에 하나의 기준일을 강제로 붙이지 않는다. 중복 참조는 한 번 계산해 재사용한다.
- **입력 안전성:** 실행 시점의 식을 고정한다. 식에 참조되지 않은 거래대금 조건 때문에 KIS를 추가 조회하지 않는다. 참조 중인 조건 삭제는 식에서 참조를 먼저 수정하도록 안내한다. 기존 중단·늦은 응답 무시를 유지한다.

데이터 조회는 사용한 조건 중 연봉이 있으면 기존 연봉 공급자의 긴 원본 이력을 요청하고 다른 조건도 같은 원본 일봉을 각자 집계한다. 같은 입력 자료에 대한 동등성과, 실제 조회 시 수신 기간·정정·누락이 달라져 생기는 결과 차이는 구분해야 한다. 특히 Wilder의 초기 이력은 결과에 영향을 줄 수 있다.

## 검증

- `npm test`: 정적 검사, **127개 단위·브라우저 검사**, 스모크 통과. 기존 118개에 이관/논리 8개와 화면 연결 1개를 추가했다. 기존 검사 스크립트·워크플로·버전 번호는 수정하지 않았다.
- NOT의 3값 진리표, 중첩/우선순위, 미확정 봉의 0·1·2봉전 관계, 서로 다른 주기의 기준일, 음수/소수 오프셋·없는 참조·깊이 제한을 검사했다.
- 기존 화면 검사에서 배경 차트의 3초 갱신 요청이 스캐너 호출 수에 섞이는 문제는 검사 초기 차트를 미선택으로 고정해 분리했다. 명시적 차트 이동, 기존 호출 횟수·결과·중단 검사는 유지했다. 운영 타이머나 공급자 요청 코드를 끄지 않았다.
- 미리보기 라이트/다크·1024px 확인: 페이지 오류 0, 자동 외부 요청 0, 가로 넘침 없음. `A AND NOT B`에서 A는 거래량 충족, B는 실제 거래대금 미수신이며 전체는 판정 불가임을 확인했다.

## 미완료와 범위

현행 영웅문4 [전체] 목록 및 실제 계산값 대조, Windows/NSIS, 실제 KIS 거래대금·대규모 조회는 미실행이다. 미팅룸의 공식 문서 카탈로그는 설계 근거이며 실행식 동등성 인증이 아니다. DI·MACD·우물/산의 실행 지원은 추가하지 않았다. 발생 횟수·연속·기간 내 창·순차검색·시장 전체 순위는 다음 계약/데이터 작업으로 남겼다.

키움 경계값·기본값·제한에 맞춘 변경이나 623행 일괄 등록, 로그인·주문·배포·병합을 수행하지 않았다. 이전 조건식이 동일 입력에서 같은 결과를 낸다는 회귀 기준과 새로운 식 기능의 동작 검사는 별도 사례로 유지한다.
