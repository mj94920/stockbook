# 거래대금 조건의 화면 진입과 검증 보완

거래대금 계산 항목(`turnover`)과 기존 KIS 조회 연결은 엔진에 있었지만 최근 기간 조건 미리보기는 거래량만 보여 주었다. 거래대금이 빠진 것으로 보이는 진입·검토 문제를 보완한다.

## 변경

- 조건검색의 **거래대금 조건 추가** 버튼으로 원화 금액 조건을 바로 만든다. 거래량(주)과 거래대금(원)은 별도 행이며 같은 값으로 취급하지 않는다.
- 거래대금 행에 실제 금액 필요, 미수신·일자/거래량 불일치 시 판정 불가 안내를 표시한다.
- 기존 ‘조건 추가’와 처음 열었을 때의 거래량 1개 기본 설정은 유지한다. 사용자 선택 없이 거래대금을 기존 AND 식에 강제로 붙이지 않는다.
- 새 검토용 HTML에는 거래량 A와 거래대금 B를 나란히 준비했다. 이것은 미리보기의 초기 설정이며 앱의 기본 검색식을 바꾸는 것이 아니다.

## 실제 자료 연결과 판정

조건식에 거래대금이 사용될 때 기존 `getChartTradingValues(code)`로 KIS KRX 실제 거래대금을 조회하고, 일자·거래량·원화 단위를 대조하는 기존 공용 계산에 전달한다. 종가×거래량으로 채우지 않는다. 한 봉의 N원 이상, 기간 내 충족 횟수, 최근 연속 충족은 모두 이 실제 금액 배열을 사용한다.

이번 변경은 데이터 공급자를 새로 구현하거나 라이브 KIS 수신에 성공한 작업이 아니다. 기존 공급자의 이력/응답 범위가 부족하면 해당 봉을 판정 불가로 유지한다. 실제 조회·Windows 검수는 남아 있다.

## 검증

- `npm test`: 정적 검사·**138개 단위/브라우저 검사·스모크 통과**. 기존 136개에 거래대금 수신 형식의 양성 단위 사례와 버튼/화면 연결 사례를 추가했다.
- 실제 금액을 담은 검사 fixture로 단일 봉·기간 내 횟수·연속을 확인했다. 같은 입력에서 횟수 조건이 충족해도 중간 미충족으로 연속 조건은 미충족이 된다.
- 거래대금 행 누락·거래량 불일치·다른 단위는 판정 불가다. 실제 금액은 기준에 미달하고 종가×거래량은 넘는 사례에서도 미충족을 유지한다.
- 화면의 바로 추가 버튼이 거래량이 아닌 `turnover` 행을 만들고, ‘원’ 단위의 수신 금액을 표시하는지 확인했다. 기간 판정에서도 봉마다 공급자를 재조회하지 않는다.
- 기존 엔진과 같은 입력 3,796개 비교도 통과한다. 계산식·돌파 경계·기간 창 정의는 바꾸지 않았다.
- 새 HTML의 1600/1024px 확인: 페이지 오류 0, 자동 외부 요청 0, 가로 넘침 없음. B는 `turnover`다.

브라우저 검사는 가상 IPC와 검사 fixture다. 실제 KIS 또는 현재 시장 금액 수신의 증거가 아니다. 버전·기존 검사 스크립트·워크플로·키/로그인은 변경하지 않았다.
