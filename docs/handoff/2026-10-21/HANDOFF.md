## #87 검증과 통합

- 정적 검사·기존 스모크 및 추가 회귀가 로컬에서 통과했다. [당시 로그](desktop-usage-npm-test.txt).
- 합성 화면은 #87의 docs/design/desktop-usage-review/에 있다. 사용자 원본 계좌 캡처를 재사용하지 않는다.
- 검사 변경: 뉴스·거래가 관심 목록과 함께 열리는 구성으로 기대값을 바꾸고 회귀를 추가했다. 검사 diff를 사람이 검토해야 한다. CLAUDE.md §1-9에 따라 `tests-approved` 없이는 CI가 main의 옛 scripts를 사용한다. 이 때문에 실패할 가능성이 있으나 실제 실패 로그를 읽기 전 단정하지 않는다. 라벨은 에이전트가 붙이지 않았다.
- CI 실행 [39539289831](https://github.com/mj94920/stockbook/actions/runs/39539289831)은 실패로 확인됐으나 이 환경의 로그 조회에 본문이 반환되지 않았다. 프록시·사용량 한도 때문이라고 추정하지 않는다.
- 실제 호가 미수신 시 무작위 잔량을 만들던 코드를 제거했다. 미수신 상태 표시가 정상이다. 이전 종목의 단가/수량과 지연 호가가 새 종목으로 넘어가지 않게 검사한다.
- #84와 merge-tree에서 index.html의 </style> 직전 CSS 추가 위치 한 곳이 충돌한다. 양쪽 CSS를 함께 보존하고 통합 후 전체 검사한다. #84 브랜치는 수정하지 않았다.
- #84+#85는 이전 임시 통합 검사가 통과했으나 #87까지 합친 Windows 실행 검증은 없다.

Windows 확인 순서: 앱 시작 → #84 자료 미리보기 열림 → 업데이트 후 테마 유지 → 정상 종료 후 이번 실행의 임시 폴더 정리 → 기존 버전 위 설치. 추가로 #87의 종합/호가/그룹/뉴스/모달 동선을 실제 해상도에서 확인한다. 모든 과정은 실제 계좌·기사 서비스와 합성 테스트를 구분한다.

## 차트 데이터 검증 인계

[chart-proof](chart-proof/README.txt)는 제품과 분리된 시험 소스다. Electron 31.7.7 고정, 별도 임시 userData 사용, API 키 불필요. npm install → npm run check → npm start로 실행한다. 검토 전 무조건 실행할 필요는 없다.

Python HTTPS로 삼성전자 300봉을 받은 기록과 Chromium에서 기록 데이터를 표시한 검증은 있다. 같은 환경의 제품 httpsGet 함수를 Node로 실행한 경로는 timeout이었다. Windows Electron main의 실제 수신·IPC는 미검증이다. 기록 데이터 표시 성공을 네트워크 연결 성공으로 세지 않는다.
공급자 간 OHLCV 불일치가 보고돼 원천 정확성·수정주가·거래소·갱신 기준 대조가 남았다. 당시 결과 파일은 과거 검증 기록이며 새 환경에서 그대로 재현됐다는 뜻이 아니다. 외인·기관 보유량과 외국인소진율을 혼동하지 않는다.

## AI·클라우드 경계

공식 CLI 상태 확인 → 로그인 확인 시 연결됨 → 명확한 미로그인 때만 공식 인증. 조회 실패는 미확인이다. 토큰 복사 금지, 공유 로그아웃은 영향 안내와 확인, 상태 재조회. 같은 PC라도 임시 HOME 격리와 인증 저장소가 다르면 공유를 보장할 수 없다.
CLI 로그인과 분석 자료 전송 동의는 별개다. 로그인 확인만으로 모델 호출·자료 전송을 하지 않는다. 공개 어댑터는 독립 작성하며 비공개 캐릭터 코드·캡슐·에셋은 복사하지 않는다. main/preload 변경은 실제 diff 검토가 필요하다.
클라우드 제안은 local SQLite 우선, 레코드 단위 동기화, 서버 사용자 격리, 별도 백업, #29/#47/#64 이후 Cloud Gate를 제안한 상태다. 공급자·비용·충돌/복원 세부 정책과 D-C1~8은 미결정이다. 다른 환경 원문을 읽은 것으로 주장하지 않는다.

## 새 환경 시작 절차

1. 저장소를 clone/fetch하고 AGENTS.md, CLAUDE.md, UI 작업이면 docs/UI-REVAMP-PLAN.md를 읽는다. 금지 폴더는 읽지 않는다.
2. main과 PR HEAD·CI·열린 in-progress/queue 이슈를 다시 조회한다. 현재 기록을 최신 상태로 간주하지 않는다.
3. 작업별 codex/* 브랜치와 별도 worktree를 쓴다. 기존 claude/*·다른 PR을 덮어쓰거나 main에 직접 push하지 않는다.
4. #87 화면 검토와 CI 실패 원인 확인부터 재개한다. 검사 승인 라벨·병합은 사용자에게 맡긴다. 통화 결정 전에 #84에 임의 값을 확정하지 않는다.
5. 필요한 조합을 임시 브랜치에서 통합하고 npm test를 통과한 뒤 Windows 검증한다. 실제 EXE를 만들지 않고 만들었다고 보고하지 않는다.
6. 프록시/TLS/보안 설정을 우회하지 않는다. 실패한 URL·런타임·오류 종류를 구분해 기록하며 서명 다운로드 URL·토큰은 문서에 넣지 않는다.

## 보존과 제외

이 PR은 문서·검증 증거만 보존한다. 앱 코드·릴리스·버전·워크플로·main/preload는 변경하지 않는다. 승인 자료는 커밋 고정 링크를 사용해 이동 중 브랜치 변경에 대비한다.
로컬 Git 백업 번들은 공개 업로드하지 않았다. 보존 중인 ui-redesign에는 미반영 변경이 있어 삭제하지 않는다. 모바일 승인 자료는 Android 전용이며 PC나 legacy PWA/TWA를 복원할 근거가 아니다.
