# 확장 차트 출처와 현재 연결 범위

원본: [6d143e4](https://github.com/mj94920/stockbook/tree/6d143e4a0860f3f23341723fcf28d877bd061a68/docs/design/desktop-chart-proof/2026-10-22)

`renderer.js`는 원본 styled-chart.js, pressure.js, investors.js, investor-panel.js의 계산과 SVG 표시를 호스트별로 묶은 것이다.
SMA/BB, 매매 압력, 투자자별 순매수 산식과 사용자 색상을 재사용한다. 일봉 종합에서는 5/10/20/60일선·거래량을 축소 표시하고 상세에서는 원본 8개 이동평균·BB·수급 표시를 제공한다. 종합 축소 차트에서는 작은 축 숫자 대신 상단 종목 가격을 읽고 상세 창에서 축을 확인한다.

일봉에서 1/3/6개월·1년은 각각 최근 22/66/132/260거래일을 표시하는 UI 범위다. 이동평균은 이 범위로 원자료를 먼저 자르지 않고 전체 보존 일봉으로 계산한다. BB 상한 +25봉은 원래 계산선을 이동한 표시이며 미래 가격 예측이 아니다.

`proof-data`는 원본 커밋의 삼성전자 일봉 1,000개 및 투자자별 5거래일 스냅샷이다. metadata.json에 원본 SHA-256을 기록한다. 마지막 일봉은 장중 미완성이고 자동 갱신되지 않는다. 데이터가 없는 다른 종목에는 이 자료를 재사용하지 않는다. 이 보존 자료 자체가 실시간 공급자는 아니다. 2026-10-26부터 Windows 앱은 별도 `provider.cjs`를 통해 선택한 국내 코드의 네이버 일봉을 조회하며, 조회 실패 때 보존 자료를 대신 표시하지 않는다.

투자자별 실제 순매수 누적은 5거래일의 독립 축이다. A/D 추정선·실제 보유량·보유율과 구분한다.
거래대금 미수신 영역은 기본 접힘이며 금액을 추정해 막대를 만들지 않는다.
키움 수치 대조·신호 수식·MACD·보유량·장기 수급은 원본 README와 USER-FORMULAS.md의 미완료 상태를 유지한다.

사용자 검토에 따라 A/D 누적 추정선은 제거했다. 실제 매집량으로 오인할 수 있고 거래량 영역 대비 추가 효용이 낮다는 판단이다. 원본 보존 커밋의 기록은 유지한다. 중단·중장기 거래량 터닝포인트는 수식 확인 전까지 임의의 이동평균선으로 대체하지 않는다.

주봉·월봉은 `series.js`에서 같은 보존 일봉을 집계한다. 주봉은 4·12·24·46·73주 이평과 1·4주 구름, 월봉은 1·5·19·6·9개월 이평을 사용한다. 월봉 구름은 사용자 확인대로 피보나치이므로 이평 구름으로 대체하지 않는다. 기준 종가선은 미확인이다. 주/월 이평은 원본에서 임의 도출한 설정이 아니라 이 대화의 사용자 확인 설정이다. 거래량·추정 매매세는 기존 계산에 집계 OHLCV를 넣어 표시하며 원식 일치가 아니다. BB는 일봉에만 유지한다.

집계는 첫 시가·최고 고가·최저 저가·마지막 종가·거래량 합계를 사용한다. 첫 집계봉은 이전 자료가 없어 이평에서 제외한다. 주/월의 마지막 집계봉은 완성 확인 전까지 미완성으로 표시한다. 조회 범위를 바꿔도 그 이전 봉을 이평 계산에 쓴다. 현재 보존 자료는 주봉 215개·월봉 50개이며 다른 종목·라이브 공급·미확인 가격 조정 계약을 추가하지 않는다.

2026-10-26 사용자 지적에 따라 차트 선택을 관심목록과 분리했다. 전종목·상단 검색·보유종목에서 고른 코드로 실제 일봉을 요청한다. `provider.cjs`는 국내 6자리 코드만 받고 고정된 HTTPS fchart 경로를 조회한다. 출처가 제공한 시가·고가·저가·종가·거래량을 검증하며 60초·최대 20종목 메모리 캐시를 사용한다. OHLC 미제공/거래량 0 행은 임의 가격으로 만들지 않고 제외 수를 표시한다. 가격 조정 기준·마지막 봉 완성은 미확인으로 표시한다. 실제 일봉에는 보존 삼성전자 투자자 자료를 붙이지 않는다. 새 데이터 파일·DB·자동 수집 작업은 추가하지 않았다.

2026-10-27: 상세 창에 별도 주기·조회 범위·지표 기간 편집, 날짜/가격 좌표에 고정된 그리기, 마우스/터치 이동·확대·십자선·봉 정보를 연결했다. 원래 증명 화면의 도구 요구를 앱 모듈로 구현했으며 알 수 없는 지표 수식은 추가하지 않았다. 월봉 거래량·추정 매매세는 계산을 유지하고 고정 높이/최대 폭/공통 중심 정렬을 적용했다. 연봉은 최대 3,000일 이력의 연도 집계와 단순 종가 1·5·10년선만 사용한다. 별도 연봉 endpoint가 아닌 일봉 집계다. 상장 이력 부족은 보간하지 않는다. 가격 상·하한의 1원 이내 정수 불일치만 정규화하고 행 수를 공개하며 더 큰 오류는 거부한다. 설정과 그림은 해당 PC의 로컬 저장이며 계좌 상태와 다른 이름의 키를 사용한다.

2026-10-27 표시 유형: 빈 캔들은 양봉·음봉 모두 몸통 비움, 볼륨캔들은 수신 거래량 비례 슬롯(최대 거래량의 1% 최소 폭)이다. 가격·거래량 원자료를 바꾸지 않는다. 매물대는 현재 보이는 집계봉의 firstDate~date에 해당하는 원 일봉 거래량을 각 저가~고가의 가격 구간 겹침 비율로 12구간에 배분한 추정 분포다. 단일 가격 봉은 해당 구간에 전량 배분한다. 실제 가격별 체결·잔존 보유·투자자 소유 자료가 아니다. 원 암호화 지표의 재현으로 주장하지 않는다.

2026-10-28 거래대금 후속: 별도 `trading-value.cjs`가 기존 KIS 인증으로 KRX 일별 거래대금 `acml_tr_pbmn`·거래량 `acml_vol` 최근 최대 100개를 조회한다. 가격 차트와 별개로 로드하며 날짜/거래량이 일치하는 수신 금액만 연결한다. 주·월의 일부 일자 금액을 전체 합계로 표시하지 않는다. 이 구현은 인증된 KIS 실수신 대조가 끝났음을 뜻하지 않는다. [모의 검증 및 미실행 범위](../../docs/design/chart-trading-value/README.md).

2026-10-28 수급 후속: `investor-provider.cjs`는 KIS `inquire-investor`가 제공한 외국인·기관·개인 순매수 수량을 모두 그대로 받는다. 가격 차트와 별도 일별 축이며 기본은 일별 순매수, 선택 시 받은 행만 0 기준으로 합산한다. 보유량/비율·개인 잔여량 추정이 아니다. [출처·제약·모의 검증](../../docs/design/chart-investor-flow/README.md). 원래 삼성전자 5일 스냅샷 파일은 수정하지 않는다.

2026-10-28 미표시 보완: KIS 실패 시 네이버 integration의 선택 종목 실수신 수급을 별도 출처로 표시한다. 실제 공개 응답으로 포스코DX·삼성전자 5일 수량/날짜를 검증했다. 네이버의 제공 기준을 KRX로 표시하거나 두 소스를 합치지 않으며, 키·토큰을 보완 호스트로 보내지 않는다. [실수신 보완 결과](../../docs/design/chart-investor-flow/live-fallback-result.json). 원래 Windows KIS 실패 원인은 미확정이다.

2026-10-28 보조지표 후속: 상세의 OBV는 수신 첫 종가를 0으로 두고 종가 방향별 거래량을 누적한다. 기본 시그널 9봉 단순평균과 선택 가능한 지수평균을 제공한다. 신저가 `lowest(C(1),Period)>C`, 과매도 `Crossdown(RSI(Period),LPercent)`는 사용자 제공 식을 사용한다. Period/LPercent·RSI 평활 방식이 미확인이라 조건은 기본 미설정이고 입력 후만 표시한다. 전체 수신 이력에서 계산하며 확대·이동으로 초기화하지 않는다. 키움 원본과의 수치 일치 검증은 별도다. [사용법·계산 기준](../../docs/design/chart-obv/README.md).

2026-10-28 조건 확인: 사용자가 제공한 키움 신호 변수 화면에서 신저가 Period=40, RSI Period=14·LPercent=30을 확인해 기본값과 초기화에 반영했다. 화면에 RSI 평활 방식은 없으므로 방식 선택 전에는 과매도 신호를 계산하지 않는다. 이전에 저장한 사용자 조건(명시적 비움 포함)은 유지하며 기본값 적용은 설정의 주기 기본값으로 제공한다.

2026-10-28 주기 구성 정정: 사용자 추가 이미지에 따라 공통으로 붙였던 OBV·신호·하단 패널을 분리했다. OBV/시그널과 10구간 매물대 추정은 주봉, 신저가 40은 일봉, RSI는 일·주봉(14/30, 방식 미선택), 거래대금/순매수는 일봉, 월봉은 추정 매매세, 연봉은 일반 거래량이다. 일봉 장기 이평은 새 이미지의 450·350, 연봉은 새 이미지의 1·3·5·6·10을 기본값으로 사용한다. 차트 유형도 주기별 저장으로 변경해 다른 주기에 같은 유형을 강제하지 않는다. 원본의 실제 보유수량·BinaryWaveMACD·월봉 피보나치 미확인 범위는 그대로다. [현행 주기별 구성](../../docs/design/chart-obv/README.md).

동일 날짜 후속 확인: 사용자가 연봉 1·3·5·6·10년과 주봉 RSI 14·30을 각각 명시적으로 확인했다.

2026-10-28 세력 입장: 사용자가 다시 제공한 구름/226일선/BB 상단의 세 조건만 전체 식으로 확인했다. 일봉 종합·상세에서 계산하며 이전 거래량·금액·양봉·등락·기울기 필터는 쓰지 않는다. A/B는 25봉 전 값, BB는 고정 20/2, 준비 기간은 226개 일봉이다. 아모레퍼시픽 2025-06-20의 네이버 실제 수신값에서 같은 날짜 조건 충족을 확인했지만 HTS 이미지와 OHLCV는 달라 전체 원식/가격 일치로 주장하지 않는다. [수식·실수신 대조·화면 검증](../../docs/design/chart-entry/README.md).

2026-10-29 후속: 사용자가 작은형님·큰형님 각각의 거래량·amount·양봉·2.5% 조건과 큰형님의 과거 3·2·1봉 전 226일선 하락 조건을 추가했다. 이전 가격 조건만의 표시는 이 두 조건 표시로 대체한다. 사용자가 amount 단위를 억원으로 최종 확인해 작은형님 150억원·큰형님 5,000억원으로 고정한다. 이전의 백만원/억원 선택 UI와 단위 미확인 보류는 제거한다. 실제 일자·거래량이 맞는 기존 KIS 금액만 사용하고 최대 100거래일 밖이나 미수신 금액을 추정하지 않는다. 기호·조건·미검증 범위는 [후속 검토](../../docs/design/chart-entry-tiers/README.md)를 따른다.
